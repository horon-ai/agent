## The core tool set

The default `core` profile reaches every built-in tool. Its allow-list is the
eighteen `CORE_TOOLS` (`bash`, `read`, `write`, `edit`, `replace`,
`apply_patch`, `agentgrep`, `ls`, `webfetch`, `websearch`, `skill_manage`,
`mcp`, `monitor`, `undo`, `ask`, `todo`, `session_search`, `swarm`) plus
`CORE_DISCOVERABLE_TOOLS` (`eval`, `bg`, `batch`, `memory`, `goal`, `lsp`,
`ast_grep`, `ast_edit`, `redo`, `hashline_edit`, `context_notes`, `codemode`
and the rest) plus `toolbox`; `irc`, `checkpoint` and `rewind` join through
their switches. A switch set to `false` removes its tool.

Eleven of them are sent eagerly with schemas in every session (`read`, `write`,
`edit`, `apply_patch`, `bash`, `ls`, `agentgrep`, `todo`, `bg`, `websearch`,
`webfetch`), and `eval` joins them when a Python interpreter is on `PATH`,
because sessions call them often. Every other tool is named in a system-prompt
index and reached through `toolbox`, which keeps the first request small and
leaves the prompt cache stable when a tool is added or removed.

Profiles: `core` (default), `full`, `acp`, `minimal`/`lite`, `none`. Choose one
with `--tool-profile`, `HORON_AGENT_TOOL_PROFILE`, or `[tools] profile`.

## Three loading tiers

| Tier | Meaning |
| --- | --- |
| `essential` | Sent eagerly and callable with no discovery step. The default. |
| `discoverable` | Sent as a deferred definition. The schema reaches the model once a tool reference names it; providers without native deferred loading drop the definition instead, and a `core` session names it in the index. |
| `off` | Not sent at all. |

Override one tool with `[tools.load_mode]`:

```toml
[tools.load_mode]
batch = "off"
memory = "essential"
ask = "essential"
```

`toolbox = "off"`, or adding `toolbox` to `[tools] disabled`, turns listing mode
off and puts every reachable tool back on the eager surface. An explicit
`discoverable` entry for `toolbox` is promoted to `essential`, because listing
would otherwise create a tool with no way to reach it.

Sessions that are not listing sessions send every core tool eagerly and get no
index: `acp`, `minimal`/`lite`, `none`, an explicit allow-list, and an SDK
`enabled` list. A session fixes its tiers once at start; reloading configuration
never moves a tool between tiers mid-session.

## The listing index

A listing `core` session's system prompt gains an `# Additional tools` section:
one instruction line — `Call one with toolbox: action "run", tool "<name>", args {}.`
— then one `- <name>: <description>` row per tool. A row carries only the first
sentence of the tool description's first non-empty line, capped at 60 characters
including the trailing `...`; the model fetches parameters with `toolbox describe`.
Some descriptions open with a sentence that fits the row; the rest are cut at the
cap, so a row is a hint and `toolbox describe` gives the full text.

The index freezes when the first tool list is locked and does not change
afterwards. `/clear` keeps it because it is the same session; only a session
restore rebuilds it.

## Edit safety

- A journal backs `undo` for file edits; `redo` and hashline anchors are on by
  default (`[tools] redo`, `[tools] hashline_edit`).
- `apply_patch` is the multi-file patch tool; `replace` is the single-string edit.
- Tool output over the condense threshold is summarized rather than dropped, and
  `read` deduplicates content it has already returned in the session.

## MCP and skills

`horon mcp` lists configured MCP servers and manages remote-server OAuth
credentials (under `HORON_AGENT_HOSTING_MODE=shared-worker`, `horon mcp list`
is refused with `HOSTED_POLICY` and exit `1`). Everything external comes in over MCP. Project-local MCP config is
skipped until its digest is trusted (`--trust-workspace` records the decision).

Skills are read through `skill://` and managed with `skill_manage`; the workspace
convention is `.horon/skills/<name>/SKILL.md`.
