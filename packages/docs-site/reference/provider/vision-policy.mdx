Status: proposed design for #572. Provider adapters already handle image input compatibility. This proposal makes the choice explicit before request construction when the selected route is text-only. [Provider models](/reference/provider/model)

## Decision

| Policy | Behavior |
| --- | --- |
| `block` | Default for text-only routes. Refuse before provider dispatch and identify the incompatible route. |
| `omit` | An explicit opt-in sends the remaining text with an omission marker and a receipt. An image-only request is refused. |
| `describe` | Explicit opt-in invokes an authorized caption model and sends caption text on the selected text-only route. |

## Boundary and receipts

Resolve the policy before attaching, converting or uploading the bytes. Cover every outbound request path, including fallback and retry. Re-evaluate the policy when a route changes. The `block` path carries no image bytes, filename, local path or URL to any provider. The `omit` path sends neither bytes nor a reference and tells the user which attachments were omitted. Existing vision-capable routes use their negotiated native image representation within their current limits.

`describe` requires an explicitly configured profile and model, explicit authorization for the image recipient and a bounded caption request. The authorizing surface confirms provider/model, attachment count and potential charge. No generic role fallback may substitute a different recipient. One caption attempt per attachment shares the parent turn's cancellation and deadline. Check input byte limits first. On unsupported capability, missing authorization or failure, report refusal. Never fall through to another caption provider. Pass the resulting caption as quoted derived user data with an explicit source marker. Record the profile/model, attachment identifier within the session and outcome without logging image data or credentials. Do not pretend the text model received the original. A subsequent retry can reuse the caption only within the same authorized turn and same attachment revision.

Keep URL upload disabled. A future URL-only route needs its own review of authenticated retrieval, recipient identity, expiration, revocation, leakage and deletion semantics before implementation. This proposal creates no upload service.

## Implementation boundaries

1. In `crates/config-types/src/named_provider.rs`, define and validate explicit policy and caption recipient fields.
2. Under `crates/base/src/provider/`, enforce native capability and block or omit before serialization, including fallback routes.
3. In `crates/app-core/src/agent/`, apply explicit caption authorization, bounds, attribution and cancellation. Validate with two isolated mock endpoints before enabling a live caption route.

## Verification

Run `cargo test --locked -p horon-agent-base --lib`. In Actions use a unique synthetic image byte marker and two isolated local mock endpoints. `block` produces zero requests to both. `omit` sends one marked text-only request and no image bytes. `describe` sends image bytes once to the configured caption endpoint, sends zero image bytes or references to the text endpoint, and labels the returned caption with the configured source. A missing or failed caption authorization, a provider swap or a cancellation must not deliver bytes to another endpoint. Check explicit policy on both direct and fallback routing.
