Status: proposed design for #550. `--trace` currently exposes runtime diagnostics. This proposal adds a separately invoked diagnostic for a configured provider stream, with a cap the operator selects before any request. Official performance measurements continue to follow the [benchmark methodology](/reference/performance/benchmark). [Provider profiles and wires](/reference/provider/model)

## Decision

| Option | Consequence |
| --- | --- |
| Aggregate ordinary agent turns | Mixes tool, context and provider time and may collect real-session content. |
| Probe a provider with an explicit request budget | Isolates the stream boundary and lets users decide the number of possible paid requests. Selected. |
| Reuse raw trace dumps | Makes output size and redaction depend on provider event payloads. |

## Request and measurement contract

The operator selects one configured profile and model, a fixed non-sensitive prompt and a request count of one to five. Preview the profile label, model, protocol, sample count, request timeout and potential charge before starting. Reject invalid or missing counts before reading credentials or opening a connection. An interactive user confirms the preview. A noninteractive invocation supplies explicit consent and a count together. A zero-request preview uses neither provider credentials nor the network. Use the production provider adapter with an isolated, minimal call. Disable retries, fallback, tools and conversation history for the diagnostic. Count each outbound attempt, including unsuccessful attempts, against the total cap. Issue requests sequentially, with a 30-second deadline per stream, and stop dispatching on cancellation.

Use a monotonic clock with start at provider dispatch. Time to first meaningful event ends on the first non-empty assistant content delta from the normalized stream. Headers, heartbeats, metadata, empty deltas and usage updates are excluded. Time to observed completion ends when the adapter recognizes a successful terminal event under its wire protocol. EOF without successful termination is `incomplete`. Report HTTP failure, protocol failure, deadline and cancellation separately. A failed sample may have a first-content time and never has a successful completion time. A valid response can complete without a content delta and contributes only a completion time.

The report carries requested and attempted counts, per-outcome counts, and the sample count and median for each metric in milliseconds. Report absent aggregate values when the corresponding sample set is empty. For an even sample count, median is the arithmetic mean of the two center values. Print bounded stable error categories and sanitized profile and model labels. Omit endpoint URLs, authorization headers, prompts, response bodies and raw errors. Use an in-memory accumulator and no writes to session history. A local result is an operator diagnostic for that configuration and sample, with no CI performance verdict.

## Implementation boundaries

1. In `src/cli/args.rs` and the dispatch path, parse the explicit count and add the preview and consent path. Prove that invalid input, preview and declined consent produce zero outbound requests.
2. In `crates/base/src/provider/`, observe normalized content and terminal events using a per-diagnostic clock. Keep observation opt-in and avoid changes to provider parsing contracts, regular usage recording and the normal request hot path.
3. Under `scripts/perf/`, provide a loopback fixture with scripted event offsets and explicit failures. Use GitHub Actions for the real adapter fixture and existing official performance gates. Review paid-request consent and secret redaction before enabling real endpoints.

## Verification

Run `cargo test --locked -p horon-agent --lib cli::` for CLI compatibility. In Actions use a loopback mock with three sequential requests, seeded order and a controllable clock.

| Scripted request | Time to first meaningful event | Time to observed completion | Outcome |
| --- | --- | --- | --- |
| Metadata at 5 ms, text at 20 ms, terminal event at 70 ms | 20 ms | 70 ms | Success |
| Text at 40 ms, EOF before terminal event | 40 ms | Absent | Incomplete |
| Terminal event at 60 ms with no text | Absent | 60 ms | Success |

Expect exactly three attempts, two successes, one incomplete, and medians of 30 ms and 65 ms with two observations each. Repeating the same script yields the same verdict. Test zero outbound requests on a rejected count, preview and declined consent, and cap enforcement when the service fails. If consent is exposed in a terminal, capture the preview and cancellation with a PTY and no real credential.
