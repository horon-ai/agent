This Reference tab is the developer documentation of horon agent: how it behaves today, with proposed designs labeled separately from current behavior. The pages are written here, in `packages/docs-site/reference/` (English) and `packages/docs-site/ko/reference/` (Korean, the same path), and every English page has its Korean pair with the same headings and tables (`scripts/ci/check_docs_pairs.py`). Paths, commands, and identifiers keep their original spelling. Moving or deleting a page updates the paths left in code, scripts, and tests in the same change.

The binary does not carry these pages. The agent reads its own English corpus in the repository's `docs/` folder, compiled into the binary and served at `horon://<path>` and by the `horon` tool; it explains each feature as the cases an agent meets. A behavior change updates the page here, the agent corpus, and any guide outside the Reference tab that repeats it. Only four pages are generated: `philosophy` and the SDK and npm pages, by `scripts/ci/sync_docs_site.py` from `PHILOSOPHY.md` and the package READMEs.

## Two modes, one agent

horon agent runs in two modes that use the same engine, daemon, sessions, tools, and configuration. In headless mode a program drives the session: `run`, the daemon (`serve`) behind the SDKs and `api-bridge`, `acp` for editors, and `rpc`. In TUI mode a person drives it through `horon-tui`. Neither mode is a reduced form of the other; they differ only in who is on the other end. The modes ship as two binaries: `horon-agent` (the agent binary, which every installation needs) and `horon-tui` (the TUI binary, a separate optional asset of the same release). [`release/INSTALL.md`](/reference/release/install) and [`runtime/TUI.md`](/reference/runtime/tui) describe how each is installed.

## Fixed requirements

Every change keeps the three rules below. The source of truth is `AGENTS.md` at the repository root.

| Requirement | What it means | Current state |
| --- | --- | --- |
| No TUI in `horon-agent` | The agent binary (`serve`, `run`, `api-bridge`, `acp`, `rpc`) never opens a screen, and its dependency graph holds no `ratatui`, `crossterm`, `horon-tui`, or `horon-agent-tui*` crate. TUI mode lives in the separate `horon-tui` package on `horon-agent-sdk`, and bare `horon` on a terminal replaces itself with that sibling binary. | Met. `scripts/ci/check_headless_graph.py` walks the resolved graph |
| ACP v1 and v2 support | `horon acp` handles both `protocolVersion` 1 and 2 and answers with the highest version both sides support. Adding v2 does not break v1. | Met. v2 negotiation lives in `src/cli/acp/v2/negotiate.rs`, v1 in `src/cli/acp/util.rs` |
| No performance regression | A change must be as fast as or faster than the baseline recorded on the same machine, build profile, and workload. A slower change is not merged. | The method and recorded numbers exist (`performance/BENCHMARK.md`, `performance/RESULTS.md`). The recorded numbers are the baseline |

## Update rules

| When this changes | Do this |
| --- | --- |
| Current behavior changes | Edit the document that describes that behavior, and the diagram in `diagram/` that draws it, in the same change. |
| You want a new document | First consider adding a section to an existing document in the right folder. A new file gets an uppercase name and a row in this table. |
| A document moves or is deleted | Fix this table and the paths in code, scripts, and tests in the same change. |
| The same content appears in two documents | Make one the source of truth and have the other point at it. |
| You want to record a measurement, acceptance note, or plan | Do not create a document; write it in the PR body or an issue. Performance numbers go only in `performance/RESULTS.md`. |
| You edit any page | Keep the pair in step: every `reference/<path>.mdx` has a Korean `ko/reference/<path>.mdx`, and `python3 scripts/ci/check_docs_pairs.py` verifies that both exist and that headings, table rows, code fences, and links match. |
| You change `PHILOSOPHY.md` or an SDK or npm README | Run `python3 scripts/ci/sync_docs_site.py` and commit the regenerated `philosophy` or `sdk/` page; `--check` in CI fails while one is stale. |
