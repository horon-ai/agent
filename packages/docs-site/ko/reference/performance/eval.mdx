상태는 #553 설계 제안이다. 기존 벤치마크 워크플로는 조건을 통제한 작업으로 지연과 자원 사용량, 내부 연산 횟수를 검사한다. 이 설계는 객관적인 채점 규칙이 있으며 직접 선택해서 실행하는 지시 준수 평가를 추가한다. [벤치마크 방법](/ko/reference/performance/benchmark)

## 설계 결정

| 선택지 | 결과 |
| --- | --- |
| 실제 프로바이더와 모델 채점 | 자격 증명이 필요하고 모델 응답의 편차에 채점 편차까지 더해진다. |
| 버전을 고정한 시험 입력과 결정적인 결과 검사 | 자격 증명 없이 같은 방식으로 채점할 수 있고 기대 결과를 하나씩 검토할 수 있다. 이 방식을 선택한다. |
| 릴리스와 벤치마크 검사에 지시 점수 추가 | 이 평가에는 별도 입력 버전과 목적이 있으므로 관련 없는 릴리스까지 함께 영향을 받는다. |

## 시험 데이터와 실행기 계약

프로젝트에서 만든 시험 데이터에 `suite_version`과 고정 사례 ID, 프롬프트, 선언한 입력 파일, 허용 출력과 객관적인 검사 조건을 둔다. 결과마다 시험 데이터 트리와 채점기 해시를 기록한다. 실행기는 사례마다 임시 작업 공간과 `HORON_HOME`을 쓴다. 각 사례에 제한된 도구 프로필만 주고 기존 환경의 설정을 읽지 않으며 사례가 바뀌면 디렉터리를 다시 만든다. 정해진 모의 서비스는 루프백에서만 동작하며 미리 정한 모델 프레임을 보낸다. 실제 프로바이더에 연결하려는 요청을 차단한다. 도구 입력에는 자격 증명을 넣지 않고 외부 영향이 없는 로컬 파일 작업을 사용한다.

초기 데이터는 최대 32개 사례를 받는다. 사례마다 프롬프트는 8 KiB, 입력과 출력은 각각 64 KiB로 제한한다. 30초가 지나거나 모델 요청이 네 번에 이르면 종료한다. 알 수 없는 시험 데이터 버전과 검사 종류, 작업 공간 밖 경로는 실행 전에 거부한다. 실행 기반에 오류가 생기면 비교 가능한 합산 점수 없이 실패로 끝낸다. 채점기는 선언한 명령 결과, 정확한 출력 바이트와 변경 경로를 검사한다. 사례의 모든 조건이 맞아야 1점을 준다. 통과 수와 총 사례 수, 사례별 결과 범주, 평가와 채점기 해시, 실행기 커밋과 모의 서비스 프로필을 기록한다. 실행 기록은 사례 ID, 요청 횟수, 제한 시간 진단용 시각과 검사 이름만 담는다.

고정 모의 서비스는 실행기와 채점기가 올바른 결과와 틀린 결과를 가려내는지 확인한다. 실제 모델의 지시 준수를 평가하려면 별도 어댑터를 승인받고 결과도 따로 기록해야 한다. 초기 평가는 모델 품질을 판정하지 않으며 릴리스 검사와 벤치마크 기준선, `suites=all`에 영향을 주지 않는다.

## 구현 경계

1. `scripts/perf/`에서 버전을 고정한 시험 데이터와 모든 실행기가 공유하는 채점 함수를 정의한다. 직접 작성한 성공과 실패 출력, 변하지 않는 기대 점수로 검사한다.
2. 기존 루프백 모의 서비스를 격리 실행기에 연결하고 GitHub Actions에서도 정확히 같은 채점기와 입력 바이트를 사용하는지 확인한다. 모의 실행 스크립트와 결과를 성능 벤치마크와 분리한다.
3. `.github/workflows/benchmark.yml`에 이름을 지정해 수동으로 실행하는 작업을 추가하고 채점 보고서를 결과물로 올린다. 저장소 읽기 권한을 설정한다. 릴리스 검사와 기본 벤치마크 실행에서는 제외한다. 외부 데이터 모음을 채택하기 전에 라이선스를 검토한다.

## 검증

`python3 scripts/perf/check_structural.py --help`로 기존 구조 검사의 명령줄이 유지되는지 확인한다. 자격 증명이 비어 있고 외부 네트워크에 연결할 수 없는 환경에서 GitHub Actions로 채점기와 루프백 실행기를 검사한다.

| 시험 지시 | 모의 출력 | 기대 점수 |
| --- | --- | --- |
| `result.txt`에 `hello`와 줄바꿈 하나만 쓰고 다른 파일은 건드리지 않는다 | `result.txt`에 정확히 그 바이트가 있다 | 통과 |
| 같은 지시 | `result.txt`에 줄바꿈 없이 `hello`가 있다 | 실패 |
| 같은 지시 | 올바른 `result.txt`와 추가 `extra.txt`가 있다 | 실패 |

합산 점수는 1/3이며 바이트 불일치와 예상 밖 경로가 한 건씩이다. 로컬 모의 서비스와 GitHub Actions에서 같은 시험 데이터와 채점기 해시로 세 사례를 실행한다. 사례별 결과와 합산 점수가 정확히 일치해야 한다. 모의 서비스 응답 기한 초과, 계약 버전 불일치 또는 외부 네트워크 연결 시도는 각각 점수 없이 실패하는지 확인한다.
