이 문서는 horon agent가 무엇을 위한 것인지, 코드가 이미 따르는 원칙이 무엇인지, omp2에서 무엇을 가져오고 무엇을 뺐는지 적습니다. 방향과 새 작업을 판정하는 기준을 말할 뿐 요구사항을 바꾸지 않습니다. 계약은 `AGENTS.md`이고 두 문서가 어긋나면 `AGENTS.md`가 우선합니다. 모든 주장에는 확인할 수 있는 파일, 이슈, 실행을 붙였습니다. 근거가 없는 문장은 측정이 아니라 결정입니다.

## horon이 무엇인가

두 모드를 동등하게 지원하는 하나의 에이전트입니다. 헤드리스 모드에서는 프로그램이 세션을 움직입니다. 일회성 명령(`run`), SDK용 로컬 소켓 harness API(`api-bridge`)를 둔 데몬(`serve`), 에디터용 stdio ACP(`acp`), 호스트 프로그램용 stdio JSONL RPC(`rpc`)가 여기에 속합니다. TUI 모드에서는 사람이 터미널에서 `horon-tui`로 세션을 움직입니다. 두 모드는 같은 데몬, 세션 저장소, 설정 위에서 같은 에이전트 루프(모델 호출, 도구, 세션, MCP)를 돌립니다. 모드는 반대편에 누가 있는지만 말하며, 어느 쪽도 다른 쪽의 축소판이 아닙니다. 두 모드는 한 릴리스 태그에서 나오는 두 바이너리로 배포됩니다. 모든 설치에 필요한 에이전트 바이너리 `horon-agent`와, `horon-agent-sdk`로 데몬을 구동하는 별도 선택 압축 파일인 TUI 바이너리 `horon-tui`입니다. 서버 코드도 Rust, TypeScript, Python SDK(`crates/agent-sdk`, `packages/sdk/typescript`, `packages/sdk/python`)로 같은 엔진을 쓸 수 있습니다.

## 코드가 이미 따르는 원칙

깨끗한 컷오버는 내부 잔재에만 적용합니다. ACP v1, harness API v1, v0.1.x가 저장한 세션 읽기는 사용자와의 약속이므로 v0.1.x 동안 유지합니다(이슈 #153).

## 새 작업의 판정 기준

다섯 질문에 모두 "예"일 때 맞는 제안입니다. `AGENTS.md`의 "Design principles" 절에 짧은 형태가 있습니다.

1. 요청당 토큰이나 턴당 CPU·fsync·메모리를 줄이거나, 측정을 더 정직하게 만듭니다.
2. CI `compare`나 구조 게이트로 잴 수 있습니다.
3. `horon-agent` 의존성 그래프와 바이너리를 키우지 않습니다.
4. ACP v1/v2, SDK, 저장된 세션을 깨지 않습니다.
5. 지운 표면을 다른 이름으로 되살리지 않습니다.

사용자 설치 Rust 패키지 구현은 3번 의존성 그래프 규칙에 한 가지 예외를 둡니다. 공용 데이터 계약 크레이트 `extension-types`(`crates/extension-types`, 패키지 `horon-agent-extension-types`)는 기존 워크스페이스 의존성만 쓰며, 작성자용 `horon-agent-extension-sdk`와 `horon-package-example`은 `horon-agent` 바이너리 그래프 밖에 남습니다. 패키지를 쓰지 않을 때의 성능과 바이너리 크기 기준선을 유지하고, 구조 성능 게이트의 `packages` 카운터(표면을 확장할 때는 바이너리 크기 검사 포함)를 지키며, ACP v1/v2, SDK, 저장 세션 호환성과 TUI 의존성 경계를 보존합니다.

## omp2에서 가져온 것

omp2는 훨씬 큰 제품입니다(도입 계획서 작성 시점에 Rust 약 117만 줄, 잠긴 패키지 1,361개. 그 계획서는 이 저장소 밖의 작업 파일이었으므로 두 수치는 어림값입니다). 아래 항목은 모두 위 기준으로 따져 골랐습니다. 표의 이슈는 모두 닫혔고, 각 행은 지금 코드가 하는 일을 적습니다.

| 아이디어 | horon이 하는 일 | 이슈 |
|---|---|---|
| 도구 스키마 세금 | 목 서버가 요청마다 본문 바이트, `tools` 바이트, 도구 개수를 기록하고 구조 게이트가 `core`의 `tools` 바이트 상한을 지킵니다(`scripts/perf/structural_budget.json`의 `prefix_tools_bytes_max`) | #147 |
| typed verdict | 모든 도구 결과가 텍스트와 함께 판정(ok, partial, truncated, withheld, rejected, failed, interrupted)을 가집니다. 모델에는 여전히 텍스트가 갑니다. 저장소, harness API, ACP, SDK 3종에 모두 들어갔고 단계마다 추가형으로 도입했습니다(`crates/tool-types/src/verdict.rs`) | #150 |
| 관대한 인자 수리와 기록 | 수리된 호출이 원본 인자와 변경 목록을 남기고, 도구별로 세고, SDK 이벤트로 내보냅니다. 새 flush는 없습니다(`crates/session-types/src/repair_record.rs`) | #151 |
| 저하 영수증 | 스키마를 줄이거나 요청 파라미터를 뺄 때마다 영수증(종류, 대상) 한 건을 남기고 SDK 이벤트로 내보냅니다. 저하가 없으면 바이트가 같습니다(`crates/harness-api-server/src/degradation_receipts.rs`) | #152 |
| 정직한 장부 | 지는 칸은 이유와 함께 결과에 남깁니다(`docs/performance/RESULTS.ko.md`). 호환 결정과 그것을 지키는 상한도 적어 둡니다(`docs/architecture/CRATES.ko.md`의 "증가 래칫") | #148, #153 |

| 원칙을 글로 남기기 | 이 문서와 `AGENTS.md`의 짧은 절 | #149 |

| `anyhow`·`SmallVec` 전면 교체 | 약 2,000곳을 고쳐도 측정되는 이득이 없습니다. 메모리 작업은 프로파일이 지목한 할당만 고칩니다 |
