상태는 #545 설계 제안이다. 현재 하네스 API는 세션 연결, 구조화된 답변과 승인 요청을 지원한다. 초대는 진행 중인 세션 하나에 제한된 역할을 부여한다. 데몬 전체를 이용할 권한은 주지 않는다. [하네스 API](/ko/reference/protocol/harness-api)

## 설계 결정

| 선택지 | 결과 |
| --- | --- |
| 기기 페어링 자격 증명 재사용 | 기기 권한이 한 세션을 넘어서고 권한을 없앨 때 다른 작업도 영향을 받는다. |
| 소유자 범위의 별도 초대 | 참가자 한 명의 권한만 없앨 수 있고 기존 소유자 연결이 유지된다. 이 방식을 선택한다. |
| 읽기 전용 스냅샷 | 비동기 공유에 알맞지만 실시간 접속 상태를 보여 주거나 작성자 입력을 받을 수 없다. |

## 권한과 표시 범위

소유자는 세션 하나에서 협업을 열고 역할과 만료 시각을 지정해 초대를 만든다. 요청 결과로 일회용 무작위 초대 비밀값을 받는다. 기본값은 초대 수락에 15분, 전체 유효 기간은 1시간이다. 두 기한 모두 만들 때 정하고 이후에는 앞당길 수만 있다. 초대 수락 후 얻는 권한은 전송 계층에서 인증한 신원, 세션 ID와 초대 세대에 묶는다. 같은 초대를 동시에 수락하면 하나만 성공한다. 인증된 협업 전송 계층이 설정돼 있어야 접근할 수 있다. 기존 인증 연결 경계를 통과하되 기기 페어링 자격 증명은 전달하지 않는다. 전송 계층은 상대 신원을 확인하고 권한 검사까지 위임받은 신원을 유지한다. 열람자와 작성자는 데몬에 직접 연결한 소유자 권한으로 동작할 수 없다.

| 동작 | 열람자 | 작성자 | 소유자 |
| --- | --- | --- | --- |
| 협업 대화와 참가자 명단 보기 | 가능 | 가능 | 가능 |
| 초대받은 세션에 일반 사용자 메시지 보내기 | 불가 | 가능 | 가능 |
| 구조화된 질문에 답하거나 승인 결정, 응답 수신 확인, 턴 개입 또는 중단하기 | 불가 | 불가 | 가능 |
| 다른 참가자 초대 또는 권한 폐기, 설정 변경, 파일 접근이나 이력 내보내기 | 불가 | 불가 | 기존 소유자 권한 적용 |
| 공유 세션에서 나가기 | 가능 | 가능 | 소유자는 협업 종료 가능 |

공유 대화는 초대를 수락한 시점부터 시작하며 화면에 표시할 사용자와 어시스턴트 텍스트, 턴 상태만 담는다. 이전 이력, 추론, 도구 데이터, 승인과 기타 비공개 이벤트는 제외한다. 명단에는 참가자별 표시 이름과 역할, 접속 상태가 나온다. 수락한 작성자 입력에는 참가자 신원을 표시한다. 해당 입력은 일반 사용자 내용으로 처리하고 에이전트 도구의 실행 결과에는 기존 소유자 승인 규칙을 적용한다. 행위자 신원은 서버가 따로 제공하는 메타데이터다. 클라이언트는 이름과 내용을 표시할 때 이스케이프한다. 명령 인자와 로그에 이름이나 비밀값을 남기지 않는다. 세션마다 게스트는 최대 8명이다. 기존 소유자 세션은 평소와 같이 동작한다.

## 퇴장과 영속 상태

인증된 참가자는 권한이 만료되거나 폐기될 때까지 다시 연결할 수 있다. 소유자는 접속과 오프라인 상태를 볼 수 있다. 참가자가 직접 나가면 그 권한을 무효화하고 협업을 끝내면 해당 세션의 모든 게스트 권한을 무효화한다. 권한 수명 주기는 영속 대화와 별도로 보관한다. 만료와 폐기는 새 입력이 데몬 대기열에 들어가는 지점에서 확인한다. 같은 권한의 입력 수락과 폐기 처리는 순서를 보장한다. 폐기가 적용되면 해당 참가자가 대기열에 넣었지만 아직 실행하지 않은 입력을 제외한다. 실행 중인 턴과 이전에 반영한 메시지는 유지하며 실행 중인 턴을 중단할지는 소유자가 결정한다. 이후 게스트에게 이력을 다시 보내거나 실시간으로 전달하지 않고 연결을 해제한다. 연결만 끊기면 만료까지 권한이 유지된다. 재시작 뒤 복구할 수 없는 권한은 거부한다. 참가자가 이미 본 텍스트는 회수할 수 없다.

## 구현 경계

1. `crates/harness-api/src/requests.rs`와 대응 이벤트 타입에 협업을 켠 연결에서 사용할 초대, 수락, 퇴장, 폐기와 명단 메시지를 정의한다. 연결의 타입 계약에 역할과 세션 범위를 드러낸다. 기존 클라이언트에는 기능 협상 없이 협업 프레임을 보내지 않는다.
2. `crates/harness-api-server/src/`에서 게스트 요청 허용 목록과 게스트 전용 이벤트 선택 규칙을 적용한다. 입력이 브리지를 넘어 유지될 수 있는 곳에서는 데몬이 수락과 폐기 순서를 책임진다. 원격 전송을 켜기 전에 다른 세션 요청 거부와 소유자 전용 승인을 검사한다. 두 경계 모두에서 신원 연결과 만료, 권한 검사를 검토한다.
3. `crates/tui/src/app.rs`를 SDK에 연결해 역할과 참가자를 보여 주고 퇴장 시 연결을 해제한다. 역할별 화면 제어는 서버 권한을 반영한다. 게스트 정책과 네트워크 처리는 터미널 화면 코드 밖에 둔다.

## 검증

기존 CLI 계약에 `cargo test --locked -p horon-agent --lib cli::`를 실행한다. GitHub Actions의 고정 입력 검증에는 격리한 데몬, 소유자, 열람자, 작성자와 시각을 제어할 수 있는 시계를 사용한다. 실제 프로바이더 호출은 필요 없다.

| 검증 동작 | 기대 결과 |
| --- | --- |
| 열람자가 연결에서 메시지 제출, 답변과 승인 요청을 보낸다 | 모두 거절한다. 세션에 해당 입력이나 승인 결정이 반영되지 않는다. |
| 작성자가 입력 하나를 보낸 뒤 대기 중인 도구 호출을 승인하려고 한다 | 입력 하나가 작성자 이름으로 기록된다. 승인은 소유자만 결정한다. |
| 소유자가 작성자의 다음 입력을 받기 전에 권한을 폐기한다 | 작성자 연결이 끊기고 새 요청이 거절된다. 소유자 연결은 유지되며 이전에 반영된 메시지는 재시작 뒤에도 읽힌다. |
| 같은 초대를 두 번 동시에 수락하거나 만료 시각에 요청한다 | 기한 전에는 수락 하나만 성공하며 만료 시각부터 같은 초대는 거절된다. |

폐기 시점의 입력 수락과 이벤트 전달을 기록한다. 다른 세션 ID, 전송 계층 신원 누락, 재연결과 명시적 퇴장도 확인한다. 터미널 검토에는 시험용 신원을 사용해 참가자 명단, 열람자 제한과 작성자 제거를 보여 주는 가상 터미널(PTY) 기록을 포함한다.
