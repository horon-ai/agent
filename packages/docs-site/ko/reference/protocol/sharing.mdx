상태는 #544 설계 제안이다. 기존 Markdown 내보내기는 로컬 파일이나 표준 출력에 기록하며 하네스 API도 같은 대화 기록을 제공한다. 제안하는 공유 흐름은 기존 내보내기가 읽는 세션 데이터에서 시작한다. [하네스 API](/ko/reference/protocol/harness-api)

## 설계 결정

| 선택지 | 결과 |
| --- | --- |
| 로컬 파일 또는 클립보드 | 오프라인에서 쓸 수 있지만 만료와 폐기를 지원하지 않는다. |
| 평문 스냅샷 호스팅 | 접근을 통제할 수 있지만 저장 서비스 운영자가 선택한 내용을 볼 수 있다. |
| 클라이언트에서 암호화한 고정 스냅샷 | 전송 계층에 평문을 보내지 않고 서비스 한 곳에서 접근 기간을 적용한다. 이 방식을 선택한다. |

## 공개 내용 선택과 게시

공유는 기본으로 꺼져 있다. 소유자는 저장이 완료된 단일 이력 지점에서 공유할 메시지를 직접 고른다. 초기 선택은 비어 있다. v1은 사용자와 어시스턴트의 텍스트만 허용한다. 추론, 도구 요청과 결과, 첨부, 시스템 텍스트, 절대 경로와 내부 메타데이터는 제외한다. 허용한 필드에 기존 비밀 가리기를 적용하고 사용자가 남은 민감한 내용을 직접 제거할 수 있게 한다. 가리기에 걸린 원본 바이트는 제외한다. 미리보기에서 게시할 내용 전체와 정확한 만료 시각을 보여 준다. UTF-8로 직렬화한 내용이 비어 있거나 1 MiB를 넘으면 업로드 전에 거부한다. 사용자 확인은 고정한 데이터와 형식 버전, 만료 시각에 묶인다. 이 중 하나라도 바뀌면 다시 확인한다. 이후 턴은 스냅샷에 반영되지 않는다.

## 전송과 수명 주기

게시 클라이언트는 공유마다 새 인증 암호화 키와 논스를 만들고 형식 버전, 불투명한 공유 ID와 만료 시각을 인증 데이터에 포함한다. 게시자는 별도 HTTPS 공유 서비스에 암호문과 별도로 생성한 무작위 읽기 토큰의 해시를 보낸다. 서비스는 암호문과 수명 주기 메타데이터를 보관한다. 브라우저 뷰어는 링크의 프래그먼트에서 토큰과 키를 읽고 토큰만 인증 헤더에 넣어 전용 서비스로 보낸 뒤 로컬에서 복호화한다. 렌더러는 대화 기록을 실행할 수 없는 텍스트로 처리하고 외부 스크립트, 원격 미디어와 분석 도구를 사용하지 않는다. 캐시와 참조 URL 전달을 끄고 로그와 처리 결과에서 토큰과 URL을 가린다. 링크 전체를 받은 사람은 만료되거나 폐기될 때까지 읽을 수 있다. 외부 전송을 켜기 전에 뷰어 배포 경로를 신뢰할 코드 출처로 검토한다.

서비스는 조회할 때마다 읽기 권한과 만료 시각을 확인한다. 링크가 없거나 만료됐거나 폐기됐거나 권한이 없으면 모두 같은 조회 불가 응답을 반환한다. 기본 유효 기간은 24시간이고 최대 7일이다. 폐기는 읽기 토큰과 별개로 인증된 소유자만 할 수 있다. 상태를 영속 저장한 뒤 완료를 응답한다. 상태가 바뀌기 전에 승인된 조회는 끝까지 진행될 수 있고 수신자는 이미 받은 데이터를 보관할 수 있다. 이후 조회를 먼저 차단한 뒤 서비스 보존 정책에 따라 암호문을 제거한다. 게시 결과를 받지 못했을 때는 소유자별 멱등 키로 다시 시도해도 공유가 하나만 생긴다. 미리보기를 취소하면 원격 상태를 만들지 않는다.

## 구현 경계

1. `crates/session-store/src/`에서 명시적으로 허용한 데이터만 담은 크기 제한 스냅샷을 만든다. 직렬화 전에 제외 항목을 확인하고 원본 이벤트나 블롭 참조를 공유하지 않는다.
2. `src/cli/sessions.rs`와 `crates/harness-api/src/requests.rs`에 소유자가 직접 미리 보고 게시하는 흐름을 추가한다. 기존 내보내기 호출 계약을 유지한다. TUI에서 제공한다면 타입이 정해진 API를 클라이언트로 호출한다.
3. 전송 계층과 뷰어를 에이전트 밖에 둔다. 호스팅, 보존 기간, 사고 대응, 암호화 의존성과 라이선스를 검토한 뒤 활성화한다. 실시간 협업은 스냅샷 프로토콜 범위 밖에 둔다.

## 검증

이슈에 지정된 회귀 검사 `cargo test --locked -p horon-agent --lib cli::`를 사용한다. 서비스를 켜기 전에 메모리 안에서 동작하는 전송 계층과 시간을 제어할 수 있는 시계를 사용해 GitHub Actions에서 고정 입력을 검사한다. 이 검사에는 네트워크와 실제 세션 데이터가 필요 없다.

| 검증 동작 | 기대 결과 |
| --- | --- |
| `hello`와 시험용 자격 증명을 선택하고 `private note`와 도구 결과를 빼고 게시한다 | 권한을 가진 뷰어는 `hello`와 가린 텍스트만 받는다. 저장한 암호문에는 평문 필드가 없고 복호화한 바이트는 미리보기와 같다. |
| 토큰 없이 조회하거나 잘못된 토큰 또는 복호화 키로 조회한다 | 처음 두 조회는 불가 응답을 받고 세 번째는 대화 기록을 표시하지 않는다. |
| 시각 100에 만료하는 공유 두 개를 만들고 시각 99에 첫 번째를 폐기한 뒤 시각 99와 100에 둘 다 조회한다 | 첫 번째는 두 시각 모두 조회할 수 없다. 두 번째는 시각 99에 조회할 수 있고 100에는 조회할 수 없다. |
| 게시 성공 응답을 버린 뒤 같은 요청을 다시 시도한다 | 같은 소유자와 멱등 키에 연결된 공유가 하나만 있다. |

취소하면 업로드가 한 건도 없고 암호화 데이터가 변조되면 인증에 실패하는지도 확인한다. 터미널 구현은 시험용 비밀만 써서 미리보기, 확인과 취소의 가상 터미널(PTY) 기록을 남긴다.
