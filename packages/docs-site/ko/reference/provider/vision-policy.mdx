상태는 #572 설계 제안이다. 프로바이더 어댑터는 이미 이미지 입력 호환성을 처리한다. 이 제안은 선택한 경로가 텍스트 전용이면 요청을 만들기 전에 동작을 명시한다. [프로바이더 모델](/ko/reference/provider/model)

## 설계 결정

| 정책 | 동작 |
| --- | --- |
| `block` | 텍스트 전용 경로의 기본값이다. 프로바이더 요청 전에 거부하고 호환되지 않는 경로를 알린다. |
| `omit` | 명시적으로 켜면 생략 표시를 붙인 나머지 텍스트를 보내고 결과를 알린다. 이미지만 있으면 거부한다. |
| `describe` | 명시적으로 켜면 승인한 설명 모델을 호출하고 그 설명을 선택한 텍스트 전용 경로에 보낸다. |

## 전송 경계와 안내

이미지 바이트를 붙이거나 변환하거나 업로드하기 전에 정책을 결정한다. 대체와 재시도를 포함해 모든 전송 경로에 적용한다. 경로가 바뀌면 다시 검사한다. `block`은 프로바이더에 바이트, 파일명, 로컬 경로나 URL을 보내지 않는다. `omit`은 바이트와 참조를 보내지 않고 어떤 첨부를 뺐는지 사용자에게 알린다. 기존 이미지 지원 경로는 현재 한도 안에서 합의한 이미지 형식을 사용한다.

`describe`는 사용자가 지정한 프로필과 모델, 이미지 수신자에 대한 명시적 승인, 크기와 시간이 제한된 설명 요청을 요구한다. 승인 화면은 프로바이더와 모델, 첨부 수와 비용 가능성을 보여 준다. 일반적인 역할 대체 규칙으로 수신자를 바꿀 수 없다. 첨부마다 설명을 한 번 요청하고 부모 턴의 취소와 기한을 따른다. 먼저 입력 크기를 확인한다. 지원하지 않거나 승인이 없거나 실패하면 거부를 알리고 다른 설명 프로바이더로 넘어가지 않는다. 설명은 출처 표시가 붙은 인용 데이터로 보낸다. 프로필과 모델, 세션 안의 첨부 식별자와 결과를 기록하되 이미지와 자격 증명은 로그에 남기지 않는다. 사용자에게 텍스트 모델이 원본을 받았다고 표시하지 않는다. 후속 재시도는 같은 승인 턴과 같은 첨부 버전에서만 설명을 재사용한다.

URL 업로드는 끈 상태로 둔다. 나중에 URL만 받는 경로를 지원하려면 구현 전에 인증된 조회, 수신자 신원, 만료, 폐기, 유출과 삭제 계약을 따로 검토한다. 이 제안은 업로드 서비스를 만들지 않는다.

## 구현 경계

1. `crates/config-types/src/named_provider.rs`에서 명시적 정책과 설명 수신자 필드를 정의하고 검증한다.
2. `crates/base/src/provider/`에서 대체 경로를 포함해 네이티브 이미지 기능을 확인하고 직렬화 전에 차단하거나 생략한다.
3. `crates/app-core/src/agent/`에서 설명 요청 승인과 상한, 출처와 취소를 적용한다. 실제 설명 경로를 활성화하기 전에 격리한 모의 엔드포인트 두 개로 검증한다.

## 검증

`cargo test --locked -p horon-agent-base --lib`를 실행한다. GitHub Actions에서는 구별할 수 있는 시험용 이미지 바이트와 격리한 로컬 모의 엔드포인트 두 개를 쓴다. `block`은 두 곳에 요청 0건을 보낸다. `omit`은 표시가 붙은 텍스트 요청 한 건을 보내며 이미지 바이트는 보내지 않는다. `describe`는 설정한 설명 엔드포인트에만 바이트를 한 번 보내고 텍스트 엔드포인트에는 바이트와 참조를 모두 보내지 않는다. 반환한 설명에는 설정한 출처가 표시돼야 한다. 승인 누락이나 실패, 프로바이더 변경과 취소가 다른 엔드포인트에 바이트를 보내면 실패다. 직접 경로와 대체 경로에서 모두 명시적 정책을 검사한다.
