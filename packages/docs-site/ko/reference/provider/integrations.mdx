## 이미지 생성

`generate_image` 도구(`docs/runtime/TOOLS.ko.md`)는 OpenAI Images 형태를 다룬다. `roles.image`를 지정한 프로파일의 `/images/generations`와 `/images/edits`다. 같은 형태를 말하는 게이트웨이는 그대로 동작하고 Horon AI Gateway도 포함된다.

자체 전송 형식을 쓰는 끝점, 예를 들어 Gemini의 `generateContent`나 Responses 내장 이미지 도구는 도구 대신 MCP로 연결한다. 모델 경로의 예외를 한 형태로 묶어 두는 방법이다.

```json
{
  "mcpServers": {
    "images": {
      "type": "http",
      "url": "https://mcp.example.com/images/mcp",
      "headers": { "Authorization": "Bearer ${IMAGE_MCP_TOKEN}" }
    }
  }
}
```

MCP 이미지 서버는 결과를 도구 결과로 돌려주므로 역할도 설정 스위치도 이 크레이트의 변경도 필요 없다. 대신 출력이 `~/.horon/generated-images/`가 아니라 도구 결과 예산에 들어간다.

## 원격 MCP 서버

HoronAgent는 로컬 stdio 서버, Streamable HTTP 서버, 레거시
HTTP+SSE 서버에 연결한다. 기존 stdio 설정은 계속 동작한다.

### 설정

원격 서버는 `~/.horon/mcp.json`이나 프로젝트의 `.mcp.json`에 추가한다.

```json
{
  "mcpServers": {
    "remote": {
      "type": "http",
      "url": "https://mcp.example.com/mcp"
    },
    "remote-with-token": {
      "type": "http",
      "url": "https://mcp.example.com/mcp",
      "headers": {
        "Authorization": "Bearer ${MCP_TOKEN}"
      }
    },
    "legacy": {
      "type": "sse",
      "url": "https://mcp.example.com/sse"
    }
  }
}
```

`http`와 `streamable-http`는 Streamable HTTP를 고른다. URL만 있고
command나 명시적 type이 없는 항목도 Streamable HTTP를 고른다. `sse`는
레거시 전송을 명시적으로 고른다. 초기화 과정에서 엔드포인트가 Streamable
HTTP를 지원하지 않는다고 나오면 HTTP 연결이 레거시 SSE로
폴백할 수 있다. 알 수 없는 전송 타입과 URL이 없는 원격 항목은 실행하지 않는다.

URL과 헤더는 stdio 설정과 같은 `${VARIABLE}` 및 `${VARIABLE:-default}`
확장을 쓴다. Authorization 헤더를 설정하면 저장된 OAuth 자격 증명보다 우선한다.
실제 자격 증명은 커밋되는
설정 파일에 넣지 않는다.

HoronAgent는 지원되는 외부 MCP 설정 소스도 읽는다. 같은
서버 이름에 로컬 stdio 정의와 원격 정의가 모두 있으면
기존 로컬 정의를 유지한다. 원격 서버를 함께 설정하려면
다른 이름을 쓴다.

### 명령

```sh
horon mcp list
horon mcp test remote
horon mcp login remote
horon mcp login remote --no-browser
horon mcp logout remote
```

`test`는 설정된 서버에 연결해 프로토콜을 초기화하고 도구를 나열한 뒤
종료한다. 연결이나 핸드셰이크가 실패하면 실패로 종료한다. LLM을 호출하거나
서버의 도구를 실행하지는 않는다.

`login`은 명시적이고 대화형이다. OAuth 메타데이터를 찾고, 지원되면
공개 클라이언트를 등록하며, PKCE와 루프백 콜백으로
authorization-code 흐름을 마친다. `--no-browser`는 시스템 브라우저를 열지 않고
인증 URL을 출력한다. 그래도 브라우저는 이 기기의
루프백 콜백에 접근할 수 있어야 한다. 인증 서버가 동적 클라이언트
등록을 지원하지 않으면 Authorization 헤더를 설정한다.

토큰은 HoronAgent home 디렉터리의 `mcp-oauth.json`에 제한된
권한으로 저장된다. 토큰은 원격 리소스 범위에 묶이고 브라우저를 열지 않고
갱신된다. 백그라운드 시작과 일반 연결 시도는 대화형 로그인을
시작하지 않는다. 자격 증명이 거부되거나 없으면 사람의 응답을 기다리지 않고
해당하는 명시적 로그인 명령을 알려준다.

MCP 관리 도구는 `url`, `transport`, `headers`로 즉석 원격 연결을 받거나,
그 필드 없이 이름이 지정된 설정 서버에 연결한다. `command`, `args`, `env`는
여전히 로컬 stdio 연결 필드다.

### 서버가 시작한 요청

서버가 클라이언트에 무언가를 물을 수 있다. 답하는 메서드는 둘뿐이고, 두 전송이 같은 함수로 답하므로
서로 어긋나지 않는다(`crates/base/src/mcp/protocol.rs:144-157`).

| 메서드 | 응답 |
| --- | --- |
| `ping` | 빈 결과. |
| `roots/list` | 연결의 루트 목록. 단 `initialize`에서 `roots`를 선언했을 때만이고, 아니면 메서드 없음 응답이다. |
| 그 밖의 메서드 | 메서드 이름을 담은 메서드 없음 응답. 서버가 조용히 기한을 기다리지 않고 답을 받는다. `sampling/createMessage`, `resources/subscribe`, `resources/unsubscribe`, `elicitation/create`가 여기 해당한다. |

`roots`는 연결에 내줄 루트 목록이 있을 때만 선언하고, 기본값은 꺼짐이다. `[mcp] expose_roots` 설정이 이 선언을 여는데,
답하면 모든 서버에 이 세션이 어느 디렉터리에서 일하는지 알려 주기 때문이다
(`crates/base/src/config/default_file.rs:400-403`). 켜면 루트 하나가 세션 프로젝트 폴더이고, 프로젝트 폴더가 없으면
프로세스 작업 디렉터리다(`crates/base/src/mcp/client.rs:113-138`). 루트 목록이 없으면 기능 선언을 빼고 `roots/list`도
거부한다(`crates/base/src/mcp/protocol.rs:76-102`). 목록은 `initialize` 뒤에 바뀌지 않으므로 서버는
`notifications/roots/list_changed`를 듣지 못한다고 통보받는다.

### 시작, 연결 대기, 프롬프트 캐싱

세션 도구 등록은 원격 네트워크 트래픽을 기다리지 않는다. 관리,
검색, 디스패치 도구는 즉시 등록된다. 유효한 캐시 도구 스키마는
백그라운드 연결이 시작되기 전에 알려진다. 연결이 성공할 때마다 그 서버의 도구가
독립적으로 게시되므로, 느린 서버가 빠른 피어의 도구를 가리거나
그 피어에 대한 관리와 호출을 막을 수 없다.
비어 있는 라이브 카탈로그는 다음 시작에서 삭제된 도구를 알리는 대신
오래된 캐시 스키마를 교체하기도 한다.

원격 핸드셰이크 전체에는 30초 기한이 있다. 자격 증명
갱신, 초기화, 레거시 폴백, 도구 나열이 모두 포함된다. 개별 도구
요청도 기본 30초다. `timeout_secs`는 정당하게 느린
도구 요청을 늘릴 수 있지만 원격 핸드셰이크 전체 기한은 늘리지 않는다. 오프라인 서버에 대한 첫
호출은 연결을 최대 30초 기다린다. 취소와 종료는
대기자를 제거하고 소유한 응답 스트림을 멈춘다. 일반 도구 호출이나
시작 경로가 대화형 OAuth 로그인을 기다리는 일은 없다.

헤드리스 모드에는 기존 동작이 하나 더 있다. `horon run`은 첫 턴 전에
유효한 캐시 스키마가 없는 켜진 서버를 최대 5초 기다린다.
웜 캐시면 이 대기를 건너뛴다. `HORON_AGENT_RUN_MCP_WAIT_MS=0`으로 끄고, 다른 밀리초 값을
주면 그 값이 예산이 된다. `HORON_AGENT_RUN_MCP=0`이면 그 실행에서 MCP 등록 자체를 건너뛴다.
꺼진 서버는 예산을 쓰지 않고,
준비 판정은 정규화된 도구 이름 접두사가 아니라 정확한 서버 식별자를 쓴다.

`auto`와 `deferred` MCP 모드에서 연결, 연결 해제, 도구 발견은
즉시 등록 도구 접두사와 정적 시스템 프롬프트를 안정적으로 유지한다. provider 고유의
지연 정의는 그 접두사 밖에 있다. KV 캐시 텔레메트리는 이제 즉시 정의만 해시하고
세므로, 지연 카탈로그 변경이 하네스가 만든 캐시 미스로
잘못 나타나지 않는다. 스키마 캐시가 차갑거나 바뀐 상태의 명시적 `eager` 모드는
여전히 의도적으로 도구 스냅숏을 다시 만들어
프롬프트 캐시 미스를 일으킬 수 있다. 웜 캐시 스키마는 바뀌지 않았을 때 그 재구성을 피한다.

### 수명 주기와 안전

원격 요청은 JSON-RPC 요청 ID, 협상된 프로토콜 버전,
서버가 지정한 세션 ID를 보존한다. 레거시 SSE 엔드포인트는
설정된 서버의 origin에 남아야 한다. MCP 자격 증명을 붙여 HTTP 리다이렉트를 따라가지 않는다.
종료는 대기 중 요청을 닫고 연결이 소유한 워커를 멈춘다.

인증이 필요한 원격 서버에는 HTTPS를 쓴다. 루프백 HTTP는
로컬 개발과 통합 테스트에 쓸 수 있다. OAuth 엔드포인트 발견과 콜백
검증은 보안 URL, 리소스 바인딩, PKCE, state 검증을 강제한다.

### 패키지가 제공하는 MCP 서버

설치된 플러그인은 `plugin.toml`에서 MCP 서버를 선언할 수 있다
(`[resources] mcp = ["resources/mcp/servers.json"]`). 각 항목은 패키지 자신의 실행
파일이나 사용자가 이미 설정한 서버를 가리킨다.

```json
{"mcpServers": {
  "echo": {"type": "stdio", "mode": "mcp"},
  "clock": {"type": "remote", "server": "corp-clock"}
}}
```

- `stdio`는 패키지의 설치된 실행 파일을 설치 루트 뒤에 `mode`(와 추가 `args`)를
  붙여 실행하며, 다른 패키지 프로세스와 같은 감독을 거친다. 다이제스트를 확인하고
  기동한 세대 동안 복사본을 고정하며, 자체 프로세스 그룹과 함께 멈춘다.
- `remote`는 엔드포인트도 자격 증명도 더하지 않는다. 사용자가 병합한 설정의 서버를
  가리키며, 패키지는 그 연결로 접속한다. 사용자가 정의하지 않은 참조는 로그를 남기고
  건너뛴다.

모든 이름은 `plugin_<id>_<name>`으로 등록되고 사용자 소스 뒤에 병합되므로, 패키지가
사용자가 쓰는 이름을 가져가지 않는다. 같은 이름을 사용자가 정의했으면 사용자 정의가
이긴다. 서버는 턴이 캡처한 카탈로그 세대를 따르며, 교체되거나 제거된 패키지는 자기
연결만 닫고 호출은 세션의 일반 도구 정책을 그대로 거친다.

## 격리 브라우저 연결 제안

상태는 #576 설계 제안이다. Horon은 설정한 MCP 서버에 연결할 수 있고 `webfetch`는 페이지 내용을 가져온다. 별도 브라우저 MCP 연결 도구는 사용자가 직접 페이지를 열고 접근성 스냅샷이나 화면 캡처를 요청할 수 있게 한다. [도구 참조](/ko/reference/runtime/tools)

| 선택지 | 결과 |
| --- | --- |
| `webfetch`에 브라우저 엔진 추가 | 기존 가져오기 경로에 브라우저 수명 주기와 의존성이 추가된다. |
| 사용자가 이미 연 브라우저에 연결 | 기존 로그인 상태와 관련 없는 탭에도 접근할 수 있다. |
| 사용자가 설정한 로컬 표준 입출력 MCP 연결 도구 | 브라우저 의존성을 에이전트 밖에 두고 검사마다 새 환경을 쓰며 기존 설정 경계를 재사용한다. 이 방식을 선택한다. |

사용자는 기존에 신뢰하는 MCP 설정으로 연결 도구를 설치하고 직접 활성화한다. 연결 도구는 선택한 페이지 하나에 임시 브라우저 환경 하나를 만들고 기존 프로필, 쿠키나 로컬 저장소를 가져오지 않는다. 초기 기능은 사용자가 시작한 페이지 열기, 접근성 스냅샷과 화면 캡처로 제한한다. 도구 출력에는 다른 페이지를 열 권한이 없다. 다른 출처는 사용자가 다시 선택해야 한다. 기본 페이지 요청, 리디렉션과 리소스 요청에 선택한 출처를 적용한다. 지원하지 않는 주소 형식과 사용자가 지정하지 않은 로컬 대상은 거부한다. 운영자가 시험용으로 정확한 루프백 출처를 지정했을 때만 루프백을 허용한다. 백그라운드 탐색, 임의 스크립트 실행, 다운로드, 폼 제출과 원격 디버깅 연결은 이 설계의 범위 밖에 둔다.

페이지를 열 때 기본 제한 시간은 15초다. 스냅샷은 접근성 노드 500개와 텍스트 64 KiB까지 반환하고 잘렸는지 표시한다. 화면 캡처는 최대 1280×720 픽셀의 화면 한 개와 인코딩한 데이터 2 MiB로 제한한다. 비활성화, 연결 해제 또는 실패 시 길이가 제한된 일반 MCP 오류를 반환한다. 연결이 끊기거나 시작 제한 시간이 지나거나 브라우저가 실패하면 대기 작업을 취소하고 환경과 브라우저 프로세스, 임시 프로필을 닫는다. 연결 도구가 시작한 브라우저만 닫도록 프로세스 소유권을 확인한다. 기본 설정에서는 캡처 데이터를 저장하거나 진단 로그에 넣지 않는다. 페이지 내용과 반환한 메타데이터는 신뢰할 수 없는 데이터로 처리한다.

### 구현 경계

1. 외부 연결 도구의 로컬 표준 입출력 계약을 정하고 기존 MCP 신뢰 모델 아래에서 설치를 확인한다. 브라우저 의존성과 프로세스, 프로필 정리는 외부 연결 도구가 맡는다.
2. 이 가이드와 `docs/runtime/TOOLS.ko.md`에 설정을 문서화한다. `crates/app-core/src/tool/mcp.rs`를 거쳐 도구 검색과 호출을 검사한다. 문제가 재현돼 좁은 수정이 필요한 경우를 제외하고 기존 MCP 관리자와 수명 주기를 사용한다.
3. GitHub Actions에서 사용자가 고른 로컬 시험 페이지와 연결 해제를 확인한다. 응답 제한 정보와 프로세스·프로필 제거 결과를 기록한다. 연결 도구를 제공하기 전에 동의, 출처 격리와 결과물 처리 방식을 검토한다.

| 검증 동작 | 기대 결과 |
| --- | --- |
| 로컬 시험 출처를 직접 선택하고 제목 하나와 이름이 붙은 컨트롤 하나가 있는 페이지를 연다 | 기존 MCP 설정으로 연결 도구에 닿으며 두 노드를 포함한 스냅샷을 받는다. |
| 노드 600개가 있는 페이지의 스냅샷을 요청한다 | 최대 500개 노드와 64 KiB의 텍스트만 반환하며 결과가 잘렸다고 표시한다. |
| 사용자가 선택하지 않은 출처로 시험 페이지가 리디렉션한다 | 연결 도구가 거부하고 그 출처로 탐색 요청을 보내지 않는다. |
| 캡처 대기 중에 연결을 해제한다 | 캡처가 취소되고 연결 도구가 시작한 브라우저와 임시 프로필이 사라진다. |

호환성을 확인하려면 `cargo test --locked -p horon-agent --lib cli::`를 실행한다. 별도 검증은 루프백만 사용하며 실제 로그인, 외부 네트워크와 기존 브라우저 프로필을 사용하지 않는다. 나중에 터미널 제어를 추가하면 명시적 선택과 연결 해제의 가상 터미널(PTY) 기록을 남긴다.

## 사용자 정의 HTTP JSON 웹 검색

JSON을 돌려주는 HTTP 엔드포인트는 무엇이든 `~/.horon/config.toml`에서 설정한다.

```toml
[websearch]
engine = "custom"
fallback_engines = []

[websearch.custom]
endpoint = "https://search.example.org/api"
method = "GET"
query_param = "q"
count_param = "count"
params = { format = "json" }
headers = { Accept = "application/json" }
header_env = { Authorization = "SEARCH_AUTH" }
results_pointer = "/data/results"
title_pointer = "/title"
url_pointer = "/url"
snippet_pointer = "/snippet"
```

이 빌드에는 로컬 엔진을 프로바이더 네이티브 검색으로 넘기는 설정이 없다.
`engine = "native"`는 선택 값으로만 남아 있고 검색 순서에서 빠진다. 그래서 그 값에
`fallback_engines`까지 비어 있으면 기본 DuckDuckGo와 Bing으로 검색한다.
`engine = "custom"`이면 설정한 엔드포인트로만 검색한다. 기존 DuckDuckGo와 Bing
기본값은 그대로다. 오류가 나거나 결과가 비면 `fallback_engines`를 순서대로 시도한다.
기본 대체 엔진은 Bing이다. 비공개 질의를 다른 곳으로 보내면 안 되면 `[]`로 둔다. 사용자
정의 엔진을 대체 엔진으로 쓸 수도 있다.

### 요청

`endpoint`는 사용자 정보와 프래그먼트가 없는 절대 HTTP(S) URL이어야 한다.
원격 서비스에는 HTTPS를 쓴다. GET과 POST만 지원하며 설정에서 대소문자를 가리지 않는다.
기본은 GET이다. `params`는 두 방식 모두에 적용되는 정적 URL 질의 매개변수이고, 같은
이름의 엔드포인트 질의 매개변수를 덮어쓴다. GET에서는 질의와 선택적인 개수가 URL
매개변수가 된다. 동적 값은 정적 값과 같은 이름의 엔드포인트 매개변수를 덮어쓴다. 모든
매개변수는 URL 인코딩한다.

POST에서 `body`는 정적 JSON 객체다(기본값 `{}`). 질의는 `query_param` 자리에 문자열로
들어가고, 개수는 `count_param` 자리에 JSON 정수로 들어간다. 이 둘은 포인터가 아니라 본문
최상위 키 그대로이며, 이미 있는 본문 키를 덮어쓴다. 예를 들면 다음과 같다.

```toml
[websearch.custom]
endpoint = "https://search.example.org/api"
method = "POST"
query_param = "search"
count_param = "limit"
params = { version = "1" }
body = { options = { safe = true } }
```

`query_param`의 기본값은 `q`다. 개수 매개변수를 보내지 않으려면 `count_param`을 생략한다.
넣을 때는 비어 있지 않아야 하고 `query_param`과 달라야 한다. 결과는 여전히 `num_results`로
로컬에서 제한한다(도구 기본값 8, 최대 20).

`headers`는 정적 헤더 값을 넣는다. 자격 증명에는 `header_env`를 쓰는 편이 좋다. 헤더
이름을 환경변수 이름에 대응시키고, 정적 헤더를 대소문자 구분 없이 덮어쓴다. 환경변수에는
필요한 경우 `Bearer `를 포함한 **전체** 값이 들어간다. 변수가 없거나 비어 있으면, 또는
헤더 값이 잘못되면 네트워크 접근 전에 실패한다. 자격 증명은 진단 정보에 복사하지 않는다.
헤더 인증을 쓸 수 있으면 URL이나 본문에 자격 증명을 넣지 않는다.

사용자 정의 요청의 제한 시간은 30초이고, 자격 증명이 다른 목적지로 전달되지 않도록 같은
호스트 리다이렉트를 포함해 리다이렉트를 따라가지 않는다. 요청 오류에서는 reqwest URL을
지운다. HTTP 오류는 상태만 보여주고 응답 본문, 설정한 URL, 헤더는 보여주지 않는다. 이런
보호 장치는 설정한 엔드포인트를 신뢰하는 일을 대신하지 않는다. 평문 HTTP는 자격 증명을
암호화하지 않고 보낸다.

### JSON 결과 매핑

포인터는 JSON Pointer(RFC 6901)를 따른다. `/`는 `~1`로, `~`는 `~0`으로 이스케이프한다.
`results_pointer`의 기본값은 `/results`이고 배열로 해석되어야 한다. 최상위 배열이면 `""`를
쓴다. 제목, URL, 스니펫 포인터는 각 배열 항목 기준 상대 경로이고 기본값은 `/title`,
`/url`, `/snippet`이다. `/link/href`처럼 중첩 경로도 지원한다. URL이 없거나 문자열이
아니거나 비어 있으면 그 항목을 건너뛴다. 제목이 없거나 문자열이 아니거나 비면 URL을 대신
쓰고, 스니펫이 없거나 문자열이 아니면 빈 값이 된다. JSON이 깨졌거나 포인터 문법이
틀렸거나 결과 매핑이 없거나 배열이 아니면 분명하게 실패하고 설정한 대체 엔진을 쓴다.
유효한 빈 배열은 결과 없음이다.
