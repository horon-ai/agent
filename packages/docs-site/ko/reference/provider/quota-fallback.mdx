상태는 #573 설계 제안이다. 순서가 정해진 모델 대체, 프로바이더와 계정 전환, 상한이 있는 요청 제한 재시도가 있다. 제안은 유효한 할당량 근거로 기존 대체 경로와 대기 중 하나를 고른다. [프로바이더 모델](/ko/reference/provider/model)

## 설계 결정

| 선택지 | 결과 |
| --- | --- |
| 선호 경로를 항상 기다림 | 근거가 없거나 오래되면 작업이 막힐 수 있다. |
| 소진한 경로를 항상 건너뜀 | 곧 초기화된다는 근거와 기다리려는 사용자 선택을 반영하지 않는다. |
| 근거와 시간 상한이 있는 정책을 선택해서 사용 | 기본 순서를 유지하고 대기와 원래 경로로 돌아가는 조건을 명시한다. 이 방식을 선택한다. |

## 근거와 경로 선택

정책은 기본으로 꺼져 있고 꺼져 있으면 기존 후보 순서를 쓴다. 정책을 켜면 프로바이더·계정·모델 범위, 관찰 시각, 한도 종류, 알 수 있는 잔여량과 제공된 초기화 시각을 기록한다. 정확히 그 범위에서 인증된 프로바이더 응답이나 검증한 할당량 정보만 근거로 쓴다. 관찰 후 최대 60초까지만 유효하고 승인 상태가 바뀌면 바로 무효화한다. 초기화 시각이 지나면 다시 시도할 수 있지만 잔여량을 보장하지는 않는다. 로컬 사용량만으로 원격 할당량을 단정하지 않는다. 없거나 만료됐거나 범위가 다른 근거로는 대기하지 않는다.

사용자는 `fallback_first` 또는 `wait_if_short`를 고르고 한 번에 기다릴 최대 시간을 0∼30초로 정한다. 소진한 후보에서 대기하려면 미래 초기화 시각을 알려 주는 유효한 근거가 필요하다. `fallback_first`는 기존 순서에서 쓸 수 있는 후보로 즉시 이동한다. `wait_if_short`는 초기화까지 시간이 설정 상한, 기존 재시도 대기 상한과 남은 기한, 요청 예산에 모두 들어올 때만 기다린다. 대체 후보가 없으면 유효한 근거와 동의가 있을 때 상한 안에서 한 번 기다릴 수 있다. 기존 취소 가능한 재시도 경로에서 대기한다. 깨어나면 상태를 다시 읽고 예산 안에서 정상 요청 한 번을 허용하거나 다른 경로로 이동한다. 초기화 근거가 오래됐거나 없으면 기존 재시도와 대체 경로 규칙을 따른다. 턴 기한을 늘리거나 별도 재시도 예산을 만들지 않는다. 토큰이나 원본 헤더 없이 이유와 범위 표시, 대기 시간을 알린다.

활성화할 때 복귀 정책 `next_turn` 또는 `session_sticky`를 정한다. `next_turn`은 다음 사용자 턴에 다시 쓸 수 있는 선호 경로를 검토한다. `session_sticky`는 사용자가 직접 바꾸거나 다시 전환해야 할 때까지 새 경로를 사용한다. 두 정책 모두 응답 중간에 경로를 바꾸지 않는다. 기존 재전송 가능 여부와 승인 규칙을 재사용한다. 완료했거나 결과가 불확실한 요청은 이 정책으로 다시 보내지 않는다.

## 구현 경계

1. `crates/config-types/src/model_roles.rs`에서 기본으로 꺼진 대기와 복귀 설정을 정한다. 기존 후보 순서를 유지한다.
2. `crates/base/src/provider/`에서 이미 승인된 프로바이더 통신의 범위가 있는 근거와 유효 기간을 정규화한다. 기존 인증과 원본 헤더 가리기 규칙을 유지한다.
3. `crates/app-core/src/agent/turn_failover.rs`에서 대체 후보를 고르고 기존 재시도 예산을 사용한다. 턴을 취소하면 대기도 취소한다. 제어 가능한 시계로 받은 결과와 경로 간 시험을 GitHub Actions에 추가한다.

## 검증

`cargo test --locked -p horon-agent-app-core --lib`를 실행한다. 시각 100초에 선호 경로가 108초까지 소진됐고 두 번째 경로를 쓸 수 있으면 `fallback_first`는 바로 두 번째 경로를 고른다. `wait_if_short`는 상한이 10초일 때 8초 기다리며 5초일 때는 다른 경로를 고른다. 시각 103초에 취소하면 대기는 끝나고 요청을 다시 보내지 않는다. 만료됐거나 없거나 다른 범위의 근거는 할당량 때문에 대기하게 만들지 않는다. 다음 턴이 각 복귀 정책을 따르는지, 비활성화하면 후보 순서를 유지하는지, 완료 요청을 다시 보내지 않는지 확인한다.
