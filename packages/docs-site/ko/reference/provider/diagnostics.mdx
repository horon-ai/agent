상태는 #550 설계 제안이다. 현재 `--trace`는 실행 중 진단 정보를 제공한다. 이 설계는 설정한 프로바이더의 스트림을 따로 진단하며 운영자가 요청을 보내기 전에 상한을 지정한다. 공식 성능 측정은 계속 [벤치마크 방법](/ko/reference/performance/benchmark)을 따른다. [프로바이더 프로필과 프로토콜](/ko/reference/provider/model)

## 설계 결정

| 선택지 | 결과 |
| --- | --- |
| 일반 에이전트 턴의 수치 집계 | 도구 처리, 문맥과 프로바이더 시간이 섞이고 실제 세션 내용을 수집할 수 있다. |
| 요청 예산을 명시하고 프로바이더에 시험 요청 | 스트림 구간만 재고 사용자가 비용이 발생할 수 있는 요청 수를 정할 수 있다. 이 방식을 선택한다. |
| 원본 추적 로그 재사용 | 출력 크기와 비밀 가리기가 프로바이더 이벤트 내용에 좌우된다. |

## 요청과 측정 계약

운영자는 설정한 프로필과 모델 하나, 민감 정보가 없는 고정 프롬프트와 1∼5회 요청 수를 고른다. 시작 전에 프로필 표시 이름, 모델, 프로토콜, 요청 수, 요청 제한 시간과 비용 발생 가능성을 보여 준다. 횟수가 없거나 범위 밖이면 자격 증명을 읽거나 연결하기 전에 거부한다. 대화형 실행에서는 사용자가 미리보기에서 확인한다. 자동 실행에는 명시적 동의와 요청 수를 함께 지정한다. 요청 없는 미리보기에서는 프로바이더 자격 증명과 네트워크를 사용하지 않는다. 기존 프로바이더 어댑터에서 격리한 최소 호출을 보낸다. 진단에서는 재시도, 대체 프로바이더, 도구와 대화 이력을 끈다. 실패한 요청을 포함해 전송을 시도할 때마다 상한에 계산한다. 스트림마다 제한 시간을 30초로 두고 순서대로 요청한다. 취소 시 새 요청을 보내지 않는다.

거꾸로 흐르지 않는 시계로 프로바이더에 요청을 보내는 순간부터 잰다. 첫 의미 있는 이벤트까지 걸린 시간은 정규화한 스트림에서 비어 있지 않은 첫 어시스턴트 본문 조각이 올 때까지로 정한다. 헤더, 연결 유지 신호, 메타데이터, 빈 조각과 사용량 갱신은 제외한다. 관찰된 완료까지 걸린 시간은 어댑터가 해당 프로토콜의 성공 종료 이벤트를 확인할 때까지로 정한다. 성공 종료 이벤트 없이 스트림이 끝나면 `incomplete`다. HTTP 실패, 프로토콜 실패, 기한 초과와 취소를 구분한다. 실패한 표본에는 첫 본문 시간은 있을 수 있지만 성공 완료 시간은 없다. 첫 본문 없이 정상 완료한 응답은 완료 시간에만 들어간다.

보고서에 요청한 횟수와 시도한 횟수, 결과별 개수, 지표별 표본 수와 중앙값을 밀리초 단위로 담는다. 해당 표본이 비어 있으면 집계값을 비워 둔다. 표본 수가 짝수면 가운데 두 값을 더해 2로 나눈다. 길이가 제한된 오류 범주와 민감 정보를 가린 프로필·모델 이름을 출력한다. 엔드포인트 URL, 인증 헤더, 프롬프트, 응답 본문과 원본 오류는 제외한다. 집계는 메모리에서 하고 세션 이력에 쓰지 않는다. 로컬 결과는 고른 설정과 표본에 대한 운영 진단으로 쓰며 CI 성능 판정과는 구분한다.

## 구현 경계

1. `src/cli/args.rs`와 명령 분기 경로에서 요청 수를 명시하도록 하고 미리보기와 동의 흐름을 추가한다. 잘못된 입력, 미리보기와 동의 거절에서 전송 요청이 0건인지 증명한다.
2. `crates/base/src/provider/`에서 진단 전용 시계로 정규화한 본문과 종료 이벤트를 관찰한다. 진단을 켠 호출만 관찰하며 프로바이더 파싱 계약, 일반 사용량 기록과 정상 요청 경로를 유지한다.
3. `scripts/perf/`에 이벤트 시점과 실패 조건이 정해진 루프백 시험 데이터를 추가한다. 실제 어댑터 시험과 공식 성능 검사는 GitHub Actions에서 실행한다. 실제 엔드포인트를 활성화하기 전에 유료 요청 동의와 비밀 가리기 방식을 검토한다.

## 검증

CLI 호환성을 확인하려면 `cargo test --locked -p horon-agent --lib cli::`를 실행한다. GitHub Actions에서는 요청 세 개, 정해진 순서와 제어 가능한 시계를 갖춘 루프백 모의 서비스를 사용한다.

| 시험 요청 | 첫 의미 있는 이벤트까지 | 관찰된 완료까지 | 결과 |
| --- | --- | --- | --- |
| 5 ms에 메타데이터, 20 ms에 본문, 70 ms에 종료 이벤트 | 20 ms | 70 ms | 성공 |
| 40 ms에 본문, 종료 이벤트 전에 스트림 종료 | 40 ms | 없음 | 미완료 |
| 본문 없이 60 ms에 종료 이벤트 | 없음 | 60 ms | 성공 |

정확히 3회 시도해 성공 2회, 미완료 1회가 나오고 표본 2개씩으로 중앙값 30 ms와 65 ms가 나온다. 같은 시험을 반복하면 판정이 같다. 상한을 벗어난 요청 수, 미리보기와 동의 거절에서 전송 요청이 0건인지 확인하고 서비스가 실패해도 상한을 지키는지 검사한다. 터미널에서 동의를 받으면 실제 자격 증명 없이 미리보기와 취소의 가상 터미널(PTY) 기록을 남긴다.
