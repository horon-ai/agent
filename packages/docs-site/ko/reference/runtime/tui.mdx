`horon-tui`는 TUI 바이너리다. 사람이 터미널에서 세션을 움직이는 horon agent의 TUI 모드가 여기에 있다. 프로그램이 세션을 움직이는 헤드리스 모드는 에이전트 바이너리 `horon-agent`에서 돌고, 두 모드는 엔진 하나와 데몬 하나를 함께 쓴다. `horon-tui`는 `horon-agent-sdk`로만 데몬과 대화하는 별도 패키지이자 별도 바이너리이므로, `horon-agent` 의존성 그래프에 터미널 라이브러리가 들어오지 않고 클라이언트의 버그가 서버를 끌어내리지 못한다.

## 실행 방법

터미널에서 인자 없이 실행한 `horon`(또는 `hrn`, `horon-agent`)은 필요하면 서버를 띄운 뒤 자기 프로세스를 형제 `horon-tui`로 넘긴다. 넘길 때 작업 디렉터리를 `--cwd`로 전달하므로 새 세션은 명령을 실행한 디렉터리에 속한다.

프로세스를 넘기기 전에 세 조건을 모두 확인한다(`src/cli/tui_handoff.rs`).

- 표준 입력과 표준 출력이 모두 터미널이어야 한다. 파이프, 파일, 닫힌 스트림은 헤드리스 모드를 유지한다. 스크립트와 CI가 그 출력을 읽기 때문이다.
- `HORON_NO_TUI`가 설정되어 있지 않아야 한다. 값이 무엇이든 설정하면 터미널에서도 헤드리스 모드를 쓴다.
- 실행 중인 실행 파일 옆에 `horon-tui` 파일이 있어야 한다. 실행 파일이 심볼릭 링크인 런처는 실제 위치에서 다시 찾는다. macOS에서 필요한 처리다.

조건이 하나라도 맞지 않으면 명령은 그 조건(`stdin and stdout are not both terminals`, `HORON_NO_TUI is set`, `no horon-tui beside this binary`), 그 조건에 맞는 해결 방법 하나, 헤드리스 대안을 담은 문장을 출력하고 0이 아닌 코드로 끝난다. 설치라는 해결 방법은 클라이언트가 없을 때만 쓴다. 파이프나 `HORON_NO_TUI`는 클라이언트가 이미 설치된 상태에서 생기므로, 그 문장은 설치 명령 대신 터미널이나 그 환경 변수를 가리킨다. 판정 전에 띄운 서버는 계속 돈다. `horon-tui`를 직접 실행하면 이 판정을 건너뛴다.

재개한 세션도 그대로 넘긴다. `horon --resume <id>`는 클라이언트에 `--session <id>`를 전달하므로, 클라이언트는 새 세션을 만들지 않고 그 세션에 붙는다. 소켓은 명령줄로 넘기지 않는다. 이미 `HORON_AGENT_SOCKET`으로 내보내져 있고, 클라이언트가 하네스 API 소켓을 스스로 찾는다.

클라이언트는 하네스 API 브리지를 거쳐 데몬에 닿고, 응답하는 소켓이 없으면 그 브리지를 띄운다. 브리지는 자기를 띄운 터미널을 위해 일하고 그 터미널과 함께 끝난다. 클라이언트가 붙어 있는 동안은 계속 응답하고, 붙은 클라이언트가 없으면 자기를 띄운 프로세스가 끝나는 즉시, 아니면 클라이언트 없이 1분이 지나면 멈춘다. 이때 단일 인스턴스 잠금을 풀고 소켓 파일(`horon-agent-api.sock`)을 지우므로, 다음 실행은 업그레이드 전에 남아 있던 브리지가 아니라 설치된 릴리스의 브리지를 띄운다. 데몬은 그동안 계속 돈다. 강제로 죽은 브리지가 남긴 소켓 파일은 살아 있는 브리지로 여기지 않는다. `horon`과 `horon-tui`는 연결을 열어 소켓을 확인하고, 아무것도 응답하지 않으면 브리지를 다시 띄우며, 새 브리지가 남은 파일을 대체한다. 손으로 정리할 것은 없다.

클라이언트는 자체 인자를 받는다.

```text
horon-tui [--socket <path>] [--session <id>] [--cwd <dir>] [--config <file>]... [--hide-thinking]
```

| 플래그 | 뜻 |
| --- | --- |
| `--socket <path>` | 찾아낸 기본값 대신 이 하네스 API 소켓을 쓴다 |
| `--session <id>` | 새 세션을 만들지 않고 기존 세션에 붙는다 |
| `--cwd <dir>` | 이 클라이언트가 만드는 세션의 작업 디렉터리 |
| `--config <file>` | 설정 파일을 하나 더 읽는다. 여러 번 쓸 수 있다 |
| `--hide-thinking` | `transcript.show_reasoning`과 무관하게 이 세션에서 모델 추론을 숨긴 채 시작한다. `ctrl+t`(기본값)로 다시 켜고 끌 수 있다 |
| `-V`, `--version` | 버전을 출력하고 끝낸다 |
| `-h`, `--help` | 사용법을 출력하고 끝낸다 |

한 번도 열리지 않은 연결은 클라이언트를 끝낸다. 이벤트 스트림이 만든 문장(예: `the event stream ended: ...`)이 배너에 남고 루프가 멈추며, 프로세스가 종료 코드 1로 끝나므로 감싼 스크립트도 실패를 알아챈다.

클라이언트가 도는 중에 끊긴 연결은 다르게 처리한다. 실패와 대화를 읽을 수 있도록 화면은 그대로 둔다. 상태 줄이 `disconnected`를 보여 주고, 전송은 경고 한 줄과 함께 거절되며 입력한 글자는 입력 줄에 남고, 대기열에 남은 메시지는 보내지 않으며, 돌고 있던 턴의 프롬프트는 거둔다. Ctrl-C로 나가고, 세션이 실패했으므로 프로세스는 그래도 종료 코드 1로 끝난다.

클라이언트는 터미널 창의 이름을 `horon · <label>`로 짓는다. 터미널을 여러 개 띄워 두면 어느 창이 어느 세션인지 알 수 있다. label은 세션 자신의 제목이고, 데몬이 제목을 붙이지 않은 세션은 작업 디렉터리의 마지막 구성 요소를 쓴다. 제어 문자는 버리고 label은 여든 글자에서 멈춘다. 셸이 정해 둔 제목은 먼저 터미널의 제목 스택에 밀어 넣었다가 정상 종료, 오류 경로, 패닉 훅 어느 쪽으로 끝나도 되돌린다. 떠난 뒤에도 창은 셸의 것이기 때문이다. 스택 쌍(`CSI 22 ; 2 t`로 넣고 `CSI 23 ; 2 t`로 되돌린다)은 확장 기능이므로 제목 스택을 유지하는 터미널에만 쓴다. xterm 계열(`TERM`이 `dumb`이 아님), Windows Terminal(`WT_SESSION`), ConEmu(`ConEmuANSI`)는 제목을 되돌리고, 그 표시가 없는 Windows 콘솔과 스스로 `dumb`이라 답하는 터미널은 제목만 받으므로 클라이언트가 떠난 뒤에도 창이 `horon · <label>`로 남는다. 표준 출력이 터미널이 아니면 아무것도 쓰지 않는다.

제목 스택을 지원하는 터미널에서는 `title.state = true`로 제목 뒤에 `running`, `waiting` 또는 `idle`을 붙일 수 있습니다. 턴이 시작하거나 끝날 때와 질문 또는 승인을 기다리는 동안 표시가 바뀝니다. 종료하면 기존 제목을 돌려놓습니다.

## 사용자 파일

다섯 파일이 클라이언트의 동작을 정한다. 넷은 `$HORON_HOME`(설정하지 않으면 `~/.horon`) 아래에, 하나는 프로젝트 아래에 둔다.

| 파일 | 범위 | 역할 |
| --- | --- | --- |
| `$HORON_HOME/tui.toml` | 모든 프로젝트 | [상태 줄](#상태-줄)을 포함한 설정 |
| `$HORON_HOME/themes/<name>.json` | 모든 프로젝트 | 색 테마와 글리프 프리셋 |
| `$HORON_HOME/keybindings.toml` | 모든 프로젝트 | 다시 배치한 키 |
| `$HORON_HOME/commands/<name>.md` | 모든 프로젝트 | 슬래시 명령 |
| `<cwd>/.horon/commands/<name>.md` | 프로젝트 하나 | 그 프로젝트의 슬래시 명령 |

다섯 파일은 시작할 때 읽고 클라이언트가 도는 동안 다시 읽는다. 설정 파일은 1초에 한 번 확인하고, 테마 파일과 키 파일도 같은 주기를 따른다.

`/info`는 터미널 호출에 적용되는 데몬의 `approval mode`를 보여 줍니다. 기본값은 `yolo`입니다. 변경하려면 데몬의 `config.toml`에서 `[tools] approval_mode`를 지정합니다.

### 설정: `tui.toml`

한 프로세스의 설정은 레지스트리 기본값, 전역 파일, 프로젝트 파일, 준 순서대로의 모든 `--config` 파일, 환경 변수 순으로 정해진다. 키마다 위 계층이 이기고, 어떤 계층도 이름을 대지 않은 키는 아래 계층의 값을 그대로 쓴다. 설정 화면은 키마다 이긴 계층을 `default`, `global <path>`, `project <path>`, `config <path>`, `env <name>`으로 보여 준다.

| 키 | 형식 | 기본값 | 환경 변수 |
| --- | --- | --- | --- |
| `theme` | 문자열 | `dark` | `HORON_TUI_THEME` |
| `symbols` | `unicode`, `nerd`, `ascii` | `unicode` | `HORON_TUI_SYMBOLS` |
| `title.state` | 참·거짓 | `false` | `HORON_TUI_TITLE_STATE` |
| `statusline.preset` | `default`, `minimal`, `custom` | `default` | `HORON_TUI_STATUSLINE_PRESET` |
| `statusline.left` | 세그먼트 이름 배열 | `["model"]` | `HORON_TUI_STATUSLINE_LEFT` |
| `statusline.right` | 세그먼트 이름 배열 | `["status"]` | `HORON_TUI_STATUSLINE_RIGHT` |
| `statusline.path_max` | 숫자 | `40` | `HORON_TUI_STATUSLINE_PATH_MAX` |
| `statusline.context_window` | 숫자 | `0` | `HORON_TUI_STATUSLINE_CONTEXT_WINDOW` |
| `editor.submit_on_enter` | 참·거짓 | `true` | `HORON_TUI_EDITOR_SUBMIT_ON_ENTER` |
| `editor.suggestions` | 참·거짓 | `false` | `HORON_TUI_EDITOR_SUGGESTIONS` |
| `transcript.tool_output_lines` | 숫자 | `3` | `HORON_TUI_TRANSCRIPT_TOOL_OUTPUT_LINES` |
| `transcript.mouse_scroll` | 참·거짓 | `true` | `HORON_TUI_TRANSCRIPT_MOUSE_SCROLL` |
| `transcript.show_reasoning` | 참·거짓 | `false` | `HORON_TUI_TRANSCRIPT_SHOW_REASONING` |
| `transcript.markdown` | 참·거짓 | `true` | `HORON_TUI_TRANSCRIPT_MARKDOWN` |
| `transcript.visual_blocks` | 참·거짓 | `true` | `HORON_TUI_TRANSCRIPT_VISUAL_BLOCKS` |
| `models.shortlist` | 모델 ID 배열 | `[]` | `HORON_TUI_MODELS_SHORTLIST` |

이 표는 설정 화면과 같은 설정 레지스트리(`crates/tui/src/settings/registry.rs`)를 따릅니다.

`statusline.path_max`는 `path` 세그먼트가 줄이기 전에 보여 줄 디렉터리의 최대 길이이고, `0`이면 줄이지 않는다. 줄인 경로는 뒤에서부터 온전한 세그먼트만 남기고 `…/`로 시작하므로, 표시가 생략한 디렉터리를 뜻한다. 구분자가 아예 없는 경로는 하나뿐인 이름 안에서 잘리고 말줄임표만 붙는다. `statusline.context_window`는 `context_pct` 세그먼트가 나누는 토큰 수이며 `0`이면 이 세그먼트를 숨긴다.

`editor.submit_on_enter = false`는 전송 키를 떼어 내므로, 그 키를 눌러도 보내지 않고 초안에 새 줄이 시작된다. `transcript.tool_output_lines`는 끝난 도구 호출의 출력을 그 줄 아래에 몇 줄 남길지 정한다. `0`이면 미리보기를 숨기고, `40`을 넘는 값은 `40`으로 자른다. `transcript.mouse_scroll`은 기본으로 켜져 있으므로 클라이언트가 마우스를 캡처하고 휠이 트랜스크립트를 움직인다. 끄면 캡처를 놓아 터미널의 텍스트 선택이 그대로 동작하고 휠도 터미널이 하던 일을 한다. 마우스를 캡처한 상태에서도 대부분의 터미널은 선택 보조 키를 누르는 동안 캡처를 우회한다. 예를 들어 Shift를 누른 채 끌면 된다. `transcript.markdown = false`는 모델의 글을 마크다운 표시까지 그대로 그린다.

`transcript.show_reasoning`은 사고 블록을 여닫는 설정이고 설정 화면의 이름은 `Show thinking`이다. `true`이면 모델의 추론을 남겨 그것이 앞서는 답 위에 흐리게 그리고, 스트리밍 조각마다가 아니라 경계(추론 종료, 도구 호출, 첫 답 조각)마다 생각 하나를 항목 하나로 확정한다. 이 설정이 꺼져 있으면 추론 조각은 도착하는 대로 버리므로, 끄면 이후 모든 턴의 사고 블록이 보이지 않는다.

`ctrl+t`(`app.toggle_thinking`, 기본 바인딩)는 파일을 쓰지 않고 프로세스가 끝날 때까지 같은 스위치를 뒤집고, `--hide-thinking`은 그 선택을 숨김으로 시작한다. 세션 선택은 설정보다 우선한다. 다른 키를 고친 설정 재적용이나 테마 변경은 이 선택을 그대로 두고, `transcript.show_reasoning` 자체가 바뀌면 그것이 더 새로운 선택이므로 세션 선택을 끝낸다. 숨기면 아직 도착 중인 생각은 버리지만 이미 확정된 생각은 화면에 남기고, 다시 보이게 하면 다음 조각부터 남긴다. 숨겨 둔 동안 버린 조각은 애초에 남기지 않았으므로 되살리지 않는다. 어느 방향이든 모델에 요청하는 추론 노력 값은 건드리지 않는다. 토글할 때마다 어느 쪽으로 바뀌었는지 트랜스크립트에 한 줄 남는다.

프로젝트 파일은 `<cwd>/.horon/tui.toml`이다. 작업 디렉터리를 읽을 수 없으면 건너뛴다. 파일의 크기나 수정 시각이 바뀐 뒤 1초가 지나면 다시 읽으므로, 손으로 고친 값이 재시작 없이 적용된다.

```toml
# ~/.horon/tui.toml
theme = "dark"
symbols = "nerd"

[statusline]
preset = "custom"
left = ["status", "model", "path"]
right = ["tokens", "context_pct", "time"]
path_max = 28
context_window = 200000
```

형식이 맞지 않는 키는 경고를 남기고 건너뛰며, 파일의 나머지는 그대로 적용된다. 모르는 키도 같은 방식으로 알린다.

### `$HORON_HOME/themes/`의 테마

테마는 `name`, `colors` 표, 선택 사항인 `vars`와 `symbols` 표를 가진 JSON 객체 하나다. `vars`는 색에 이름을 한 번 붙이고 `colors`가 그 이름을 쓰거나 색을 직접 적는다(`#rrggbb`). 깨진 파일은 이전 테마를 유지하고 경고를 남기므로, 인터페이스가 스타일 없이 남지는 않는다.

```json
{
  "name": "mine",
  "vars": { "fg": "#c0caf5", "blue": "#7aa2f7" },
  "colors": {
    "accent": "blue",
    "border": "#3b4261",
    "muted": "#565f89",
```

### 키 배치: `keybindings.toml`

이 파일은 동작 아이디를 그 동작이 응답할 키에 연결한다. 항목 하나가 그 동작의 기본 키를 모두 대체하고, 빈 배열은 동작을 끈다.

```toml
# ~/.horon/keybindings.toml
"app.submit" = ["enter", "shift+enter"]
"editor.complete" = []
"app.interrupt" = ["ctrl+x"]
```

동작 아이디는 점으로 이어진 이름이므로 따옴표로 감싼 키로 적어야 한다. `"app.interrupt" = [...]`는 그 동작을 가리키고, 따옴표 없는 `app.interrupt = [...]`는 중첩 표가 되어 클라이언트가 `app`이라는 모르는 동작으로 알리고 무시하므로 기본 키가 모두 그대로 남는다.

키는 수정자 `ctrl`, `alt`, `shift`를 아무 순서로 키 이름 앞에 적는다(`Control+J`와 `ctrl+j`는 같은 키다). 문자 키는 시프트를 글자 자체에 담으므로 `A`와 `shift+a`는 한 바인딩이고, 나머지 키는 시프트를 따로 가지므로 `shift+enter`가 `enter`와 다른 키다. 터미널이 수정자를 더 붙여 보고한 키도 같은 키의 바인딩에 응답한다. `alt+left`는 `left`처럼 커서를 옮긴다.

잘못된 내용은 거절이 아니라 경고다. 모르는 동작 아이디, 배열이 아닌 값, 읽을 수 없는 키 이름, 한 범위에서 같은 키를 주장하는 두 동작이 각각 트랜스크립트에 한 줄을 남긴다. 키를 다투면 선언 순서가 앞선 동작이 그 키를 가진다.

### 명령 파일

`.horon/commands`(프로젝트)나 `$HORON_HOME/commands`(모든 프로젝트) 아래의 마크다운 파일은 파일 이름을 딴 슬래시 명령이 된다. 이름이 같은 프로젝트 파일이 사용자 파일을 이긴다. 이름이 같은 내장 명령이 있으면 그 파일 명령은 완전히 가려지고 `/help`가 `(shadowed by the built-in)`으로 표시한다. 이름이 같은 하네스 명령보다는 파일이 이긴다.

두 `---` 줄 사이의 선택 블록에는 `key: value` 줄을 적는다. 읽는 키는 `description`과 `argument-hint` 둘뿐이다. 설명이 없으면 본문 첫 줄을 `/help`에 보여 준다.

```markdown
---
description: Review a diff against the project rules
argument-hint: <path>
---

Read $1 and review it against the rules in AGENTS.md. Extra context: $ARGUMENTS
```

`/review src/main.rs`는 `$1`을 `src/main.rs`로, `$ARGUMENTS`를 인자 문자열 전체로 바꾸고, `$2`부터 `$9`는 나머지 낱말이 된다. 치환은 한 번만 도므로 인자 본문에서 자리 표시자를 다시 찾지 않는다. 치환 결과가 비면 빈 메시지가 아니라 오류다.

## 편집기

`editor.suggestions = true`로 지정하면 현재 세션에서 이미 보낸 글을 참고해 초안에 이어 쓸 내용을 표시합니다. Ctrl+Right로 제안을 초안에 넣고 Esc로 닫습니다. 초안이 바뀌면 이전 제안은 사라집니다. 제안은 로컬에서 만들며 네트워크 요청은 보내지 않습니다.

입력 줄은 초안을 따라 자란다. 줄마다 한 행이고 최대 여덟 행까지 자라며, 그보다 긴 초안은 제 안에서 스크롤한다. 초안이 자라는 동안에도 대화는 최소 세 행을 지키므로 긴 메시지가 화면 전체를 가져가지 않는다.

`enter`는 보내고 새 줄 키는 새 줄을 시작한다. `editor.submit_on_enter = false`이면 전송 키가 대신 새 줄을 시작하고 키보드로는 아무것도 보내지 않는다. 붙여넣기 없이 여러 줄 메시지를 쓰는 한 방법이다.

마지막 글자가 `\` 하나인 초안은 보내지 않는다. 백슬래시를 떼고 그 자리에 새 줄을 넣으며, 다음 `enter`가 완성된 메시지를 보낸다. 초안은 편집기에 그대로 남으므로 이스케이프는 그 자리에서 줄을 잇는 일을 한다. 끝에 백슬래시 두 개가 이어지면 적은 그대로 보낸다.

붙여넣기는 한 덩어리로 받는다. 클라이언트는 도는 동안 터미널의 bracketed paste 모드를 켜 두므로, 세 줄짜리 붙여넣기가 `Paste` 이벤트 하나로 도착해 메시지 세 개로 보내지지 않고 초안 하나로 남는다. 이 모드는 정상 종료, 오류 경로, 패닉 훅에서 끈다. 모드를 켠 채 죽은 클라이언트가 다음 프로그램에 이스케이프 코드를 붙여넣게 만들기 때문이다. 모드를 지원하지 않는 터미널은 아무것도 답하지 않고, 붙여넣기는 평범한 키 입력으로 도착한다.

최근 초안 백 개를 `up`과 `down`을 위해 남긴다. 걷기는 가장 최근 항목에서 시작하고 그 항목을 지나면 걷기를 시작할 때 화면에 있던 초안이 돌아오므로, `up`을 두 번 눌러도 쓰던 글이 사라지지 않는다. 같은 메시지를 연달아 보내면 항목 하나만 남고, 초안을 고치면 걷기가 끝난다. 다음 `down`이 고친 내용을 걷기 시작 항목으로 덮지 않는다.

`ctrl+r`은 그 초안들을 최신 순 목록으로 연다. `up`을 너무 여러 번 눌러야 닿는 초안을 찾을 때 쓴다. 행마다 초안의 첫 줄을 쓰고 여러 줄이면 줄 수를 덧붙이며, 초안 전체는 미리보기 창에 보여 준다. 모델과 세션 명령이 쓰는 것과 같은 선택 목록이므로 글자를 입력하면 걸러지고, `enter`는 고른 초안을 보내지 않고 편집기에 되돌려 넣는다. `esc`는 목록을 닫고 그 전에 있던 초안을 남긴다. 초안은 클라이언트의 것이므로 목록은 여는 순간 이미 완성되어 있다.

커서는 바이트가 아니라 표시 칸으로 놓이므로 넓은 글자는 두 칸을 센다. 입력 줄이 화면보다 넓어지면 커서 앞 글자를 왼쪽부터 버리고 한 칸을 남겨, 커서가 오른쪽 끝에 계속 보이게 한다.

## 트랜스크립트

도구 호출은 머리 행 하나와 그 아래 행으로 그린다. 머리 행은 호출 이름, 짧은 인자 요약, 결과를 담는다. 요약은 그 호출 자신의 JSON에서 첫 번째로 쓸 만한 필드를 `command`, `file_path`, `path`, `pattern`, `query`, `url`, `name`, `prompt` 순으로 고르고, 행에 남은 칸에 맞게 자른다. 결과는 `◐ running`, `✓ done`, `✕ failed`에 걸린 시간(`1.4s`, `2m 05s`)을 붙인다. 승인 게이트가 거절했는데 아직 아무도 결정하지 않은 호출은 `◐ needs approval`로 시간 없이 그린다. 실행되지도, 실패하지도 않았기 때문이다.

결과는 호출 아이디로 호출에 붙으므로, 나란히 돈 두 호출이 결과를 바꿔 받는 일이 없고, 시작을 보지 못한 호출의 결과는 다른 호출의 행에 붙지 않고 제 행을 얻는다. 끝난 호출은 머리 행 아래에 출력 미리보기를 남긴다. 기본 세 줄이고 줄마다 160칸으로 자르며, 미리보기에 없는 행은 `+N lines`로 센다. 실패는 메시지를 머리 행이 아니라 제 행에 적는다. 메시지가 보통 화면보다 길어 머리 행에 넣으면 인자와 시간을 오른쪽 밖으로 밀어 내기 때문이다.

미리보기가 무언가를 가리는 가장 최근 호출의 표시에는 나머지를 보여 주는 키가 적힌다. `+N lines · ctrl+o expands`이고, 여기서 키는 지금 적용된 배치가 `app.expand_tool`에 준 키다. 그 키는 그 호출의 출력 전체를 그리고 다시 누르면 미리보기로 되돌리며, 바뀐 블록이 대개 있는 대화 끝으로 보기를 옮긴다. 보여 줄 것이 남아 있지 않으면 `no tool output to expand`라고 알린다. 잘린 호출 가운데 최근 열여섯 개의 글 전체를 호출마다 최대 64 KiB까지 남기고, 그보다 긴 출력은 글자 경계에서 멈추며 남긴 마지막 줄이 `… output truncated`다. 행의 오른쪽 끝만 잘린 호출도 잘린 것으로 세어 줄 수 대신 `cut`을 달고, 남긴 글이 창 밖으로 밀려난 호출은 사라진 보기를 약속하지 않도록 키 이름을 달지 않는다.

승인 게이트가 거절한 호출은 데몬의 문장 전체가 아니라 짧은 이름 하나로 그린다. 옆의 프롬프트가 이미 그 질문을 하기 때문이고, 그 이름은 요청의 상태를 따른다. 결정을 기다리는 동안 머리 행은 `◐ needs approval`이고, 답이 나면 그 답을 적는다. `• allowed`, `• allowed always`, `n`이나 `esc`면 `✕ denied`, 답 없이 프롬프트가 사라지면(연결 끊김, 취소된 턴) `✕ not answered`다. 이 셋 중 어느 것도 `failed`가 아니다. 호출은 실행되지 않았고, 게이트가 붙잡았을 뿐이므로 모델이 도구를 다시 불러야 한다. 그 프롬프트에 답해도 호출은 실행되지 않는다. 결정을 기록하고 모델이 도구를 다시 불러야 하며, 트랜스크립트가 그 사실을 적는다.

`notify_pattern`을 지정한 `bash` 작업은 실행한 세션의 트랜스크립트에 일치한 출력을 실시간으로 표시합니다. 각 알림에는 작업과 표준 출력 또는 표준 오류 구분이 표시됩니다.

피할 수 있었던 프롬프트 캐시 미스는 관련 요청 뒤에 표시됩니다. 원인과 다시 보낸 토큰의 대략적인 수가 표시되며 프롬프트 원문과 캐시 식별자는 빠집니다. 모델이나 프로바이더 변경, 만료 또는 이유가 기록된 무효화에는 표식을 붙이지 않습니다. 데몬의 `config.toml`에서 `[features] kv_cache_miss_notices = false`를 지정하면 보고를 끌 수 있습니다.

대화를 거슬러 읽을 수 있다. `pageup`, `pagedown`, `shift+up`, `shift+down`이 보기를 붙잡고 `ctrl+end`가 끝으로 돌아오며, `transcript.mouse_scroll`이 캡처를 쥐고 있는 동안(기본값) 마우스 휠이 한 칸에 세 줄씩 움직인다. 보기를 붙잡은 동안 맨 아래 행이 `↓ N rows below`를 보여 주고, 붙잡은 보기가 아직 보여 주지 않은 행이 도착하면 `· new output`을 덧붙인다. 보기를 끝에서 떼면 그 세기의 기준점을 잡으므로, 첫 `↓ N rows below`는 사용자가 보던 행부터 센다.

어시스턴트 글은 마크다운으로 그린다. 제목, 강조, 인라인 코드, 목록, 인용, 펜스 코드, 가로줄을 다룬다. 목록은 최대 여섯 단계까지 중첩되고, 단계마다 두 칸 또는 탭 하나를 쓰며, 모델이 적은 들여쓰기에서 중첩을 그린다. 펜스 코드는 적힌 글자를 그대로 두고, 여는 펜스 줄이 완성되면 그 첫 낱말을 언어 표시로 그리므로, 절반만 도착한 ` ```ru `가 잠깐 표시를 띄웠다가 바뀌지 않는다. 표, 링크, 렌더러가 다루지 않는 문법은 모델이 적은 원문 그대로 남는다. 글을 지우면 모델이 한 말을 잃기 때문이다. 줄바꿈된 행은 이어지는 행의 들여쓰기를 지키므로, 중첩된 항목은 줄이 바뀐 뒤에도 중첩으로 읽힌다. 새 턴은 앞 턴에서 한 행 비운 아래에서 시작한다.

`diagram` 코드 블록은 `load -> parse -> render`처럼 한 줄 흐름을 그립니다. 이름을 최대 8개까지 넣을 수 있고 이름 하나는 24글자와 표시 칸 24개 이하여야 합니다. 원문이 4 KiB를 넘거나 흐름이 창 너비를 넘으면 원문을 표시합니다. 미완성 블록과 잘못된 문법도 원문으로 남습니다. `transcript.visual_blocks = false`를 지정하면 모든 흐름을 원문으로 표시합니다.

`transcript.markdown = false`는 이 렌더링을 끄고 같은 글을 표시까지 그대로 그린다.

## 세션 할 일

`Todos` 영역은 연결한 세션에 저장된 할 일에서 현재 작업과 차단된 항목을 먼저 보여 줍니다. 각 항목에는 그룹 이름이 표시되고 차단된 항목에는 사유가 붙습니다. 제목에는 완료한 항목 수와 화면에 들어가지 않은 미완료 항목 수가 표시됩니다. 터미널 높이가 낮으면 대화와 입력 줄을 먼저 표시합니다.

세션에 연결하면 저장된 목록을 읽고 변경이 저장되면 다시 읽습니다. 세션을 바꾸면 이전 목록을 지웁니다. 데몬이나 브리지가 실시간 갱신을 지원하지 않으면 영역을 숨깁니다.

## 턴 상태

한 번에 턴 하나가 돈다. 도는 턴 중의 Enter는 글자를 보내지 않고 대기열에 넣는다. 트랜스크립트가 `queued: <text>` 행으로 보여 주고, 메시지는 도는 턴이 끝나면 입력한 순서대로 나간다. 턴을 취소해도 대기열은 남는다. 대기열은 멈춘 턴이 아니라 다음 턴의 것이기 때문이다.

`esc`는 도는 턴을 멈추는 대신 대기 중인 메시지를 그 턴으로 보낸다. `queued: <text>` 행마다 모델이 받은 메시지가 되고 순서는 입력한 순서이며, 공지 하나가 `sent into the running turn`이라고 알린다. 대기 중인 메시지가 없으면 넘길 것이 없으므로 `esc`는 턴을 멈춘다. 클라이언트가 놀고 있을 때는 아무것도 하지 않으므로 잘못 누른 키가 세션을 끝내지 못한다. 한 번에 전달 하나만 기다리므로, 첫 전달의 답이 아직 오지 않았을 때의 두 번째 `esc`는 나중에 구분할 수 없는 메시지를 쌓지 않고 턴을 멈춘다. 거절은 경고 한 줄이고 `could not send the queued messages into the turn` 뒤에 하네스 자신의 문장이 붙으며, 메시지는 제 순서대로 대기열 앞으로 돌아간다. 전달의 답이 오기 전에 다른 세션으로 옮겨 가도 그 전달이 새 세션의 `esc`를 붙잡지 않으므로, 그 세션의 첫 `esc`는 다시 전달한다. 늦게 도착한 답은 그래도 처리되며, 받아들여졌으면 화면이 달라지지 않고 거절이면 하네스가 쓴 문장 그대로 경고 한 줄이 남고 대기열에는 아무것도 돌아가지 않는다. 그 글은 클라이언트가 떠나온 세션의 것이기 때문이다. `ctrl+c`는 턴이 돌면 취소하고 돌지 않으면 나가며, `ctrl+d`는 언제나 나간다.

턴으로 보낸 것을 데몬이 아직 붙잡고 있는 채 턴이 끝나면 `the turn ended before reading everything sent into it; the next turn carries the rest`라고 알린다. 이 공지에는 개수도 키도 적지 않는다. 데몬이 세는 것은 세션을 위해 붙잡은 항목 전부여서, 메시지 여러 개를 담은 전달 하나가 한 항목이고 배경 결과나 다른 클라이언트의 메시지도 각각 한 항목이기 때문이다.

`/model`로 고른 모델과 `/effort`, `shift+tab`, 사다리 목록으로 고른 노력 단계는 턴이 도는 동안 보내지 않는다. 데몬이 그 요청에 답하는 것은 도는 턴이 에이전트를 놓아준 뒤이기 때문이다. 둘은 턴이 끝날 때 모델, 노력 단계, 가장 오래된 대기 메시지 순으로 나간다. 그때까지 클라이언트는 `the turn is still running; the model changes to <name> once it ends` 또는 `the turn is still running; the reasoning effort changes to <level> once it ends`라고 말한다. `/new`, `/switch`, `/resume`도 같은 이유로 기다린다. 턴이 도는 동안에는 `the turn is still running; /<name> works once it ends`로, 미뤄 둔 변경이 아직 적용 중이면 `a held model or effort change is still being applied; /<name> works in a moment`로 답하고, 연결이 끊겼으면 바꿀 세션이 없다는 경고를 남긴다.

실패한 전송은 메시지로 그리지 않는다. 클라이언트는 사용자 행을 거두고, 글자를 입력 줄로 되돌리고(입력 줄에 이미 다른 글이 있으면 대기열에 넣고), 상태를 `idle`로 돌린 뒤 이유를 담은 경고 한 줄을 남긴다. 대기열은 다음 턴이 끝나거나 사용자가 다시 보낼 때까지 붙잡아 두므로, 계속 거절하는 하네스가 거절된 전송을 반복으로 만들지 못한다.

연결이 끊기면 상태 줄이 `disconnected`를 보여 주고, 대기열은 보내지 않고, 그 턴의 프롬프트는 거두고, 전송은 글자를 입력 줄에 남긴 채 거절된다. 그 상태에서 Ctrl-C로 나간다.

## 프롬프트

승인과 질문은 입력 줄 위에 그려지고, 답할 때까지 모든 키를 가져간다.

승인은 대기열이다. 첫 호출이 화면에 있는 동안 승인이 필요한 두 번째 호출은 그 뒤에서 기다리고, 화면의 프롬프트가 `N more prompt waiting` 줄을 덧붙인다(하나면 `1 more prompt waiting`). 그래야 두 번째 승인이 첫 번째의 반복으로 읽히지 않는다. 프롬프트는 호출의 동작과, 트랜스크립트가 거절이 적어 둔 요청 아이디로 그 호출과 짝을 지을 수 있을 때 그 호출의 인자를 보여 준다. 프롬프트가 다른 호출의 명령을 보여 주는 일은 없다.

`y`는 한 번 승인하고, `a`는 승인하면서 이후 같은 호출도 묻도록 하고, `n`이나 `esc`는 거절한다. 승인은 그 턴보다 오래간다. 요청은 데몬의 대기열에 제 기한과 함께 남으므로, 프롬프트를 잃으면 답할 유일한 방법을 잃는다. 승인해도 호출은 실행되지 않는다. 트랜스크립트는 결정을 `you allowed <action>: the model has to call it again before it runs`로, `a` 키였으면 `you allowed <action>: recorded once (the daemon keeps no always-rule), so the model has to call it again`로, 거절이면 `you denied <action>: the call will not run`로 적는다. 모델이 도구를 다시 불러야 실행되기 때문이다.

`ask` 도구의 질문은 `(1/2)` 세기와 함께 하나씩 그린다. 단일 선택 질문은 선택지의 숫자로 답하고, 다중 선택 질문은 숫자로 켜고 끈 뒤 `enter`로 확정하며, 고른 선택지는 `[x]`를 단다. 추천 선택지에는 `(recommended)`가 붙는다. `esc`는 질문을 연 채로 둔다. 그 도구에는 거절 경로가 없고 제 기한을 스스로 정하므로, 프롬프트를 닫으면 답할 유일한 방법이 사라진다. 모든 질문에 답하면 `you answered the ask tool (N answers): the call resumes`가 남는다. 도구가 재시도를 위해 기억되는 것이 아니라 이 연결에서 답을 기다리기 때문이다.

프롬프트는 그 턴이 취소될 때, 턴이 끝날 때(질문만), 연결이 끊길 때 거둔다. 거두기는 무엇을 버렸는지 알리는 공지 한 줄을 남긴다. 예를 들어 `the turn was cancelled; 2 prompts withdrawn`이다.

## 슬래시 팝업과 `/help`

`/`를 입력하면 입력한 글자와 맞는 명령의 목록이 열린다. `/help`가 보여 주는 것과 같은 명령이고 스킬도 들어가며, 가장 잘 맞는 순서로 설명과 함께 놓인다. 거르기는 부분 수열 맞추기라서 `/mdl`이 `model`을, `/rvw`가 `review`를 찾고, 입력한 글자로 시작하는 이름이 그저 닮기만 한 이름보다 앞선다. 선택된 행은 왼쪽 칸에 입력 줄과 같은 표시를 달고, 이름 가운데 글자가 맞은 자리는 행 양식 위에 밑줄로 그린다. 목록은 최대 여덟 행이고 선택을 따라 창이 움직인다. `up`과 `down`이 선택을 옮기고, `tab`이 고른 명령을 채우고, `esc`가 목록을 닫는다. 팝업이 가장 위층이므로 첫 `esc`는 언제나 팝업을 닫고, 두 번째 `esc`라야 턴에 작용한다. 팝업이 떠 있는 동안에는 완성 힌트를 그리지 않는다. 목록이 힌트가 할 말을 이미 하기 때문이다. 목록은 입력한 이름과 정확히 같은 행이 있고 그 이름으로 시작하는 다른 행이 없을 때에만 스스로 닫힌다. `resume`과 `resume_all`은 고를 것을 남기고, 글자가 그저 닮기만 한 행은 고를 것이 아니므로 완성된 이름을 붙잡아 두지 않는다.

`/help`는 명령을 출처별로 묶어 설명 열을 맞춰 출력하고, 그 아래에 키를 붙인다. 키 목록은 배포된 기본값이 아니라 지금 적용된 키 배치로 만들므로, 다시 배치한 키는 새 바인딩으로 나오고 파일이 끈 동작은 `(unbound)`로 나온다. `/help <command>`는 목록 전체 대신 명령 하나를 보여 준다. 명령이 선언한 인자 힌트를 붙인 이름, 설명, 나온 출처를 쓰고, 내장 명령이 가리고 있는 명령 파일이면 파일이 아니라 내장이 실행된다는 설명을 덧붙인다. 앞의 슬래시는 붙여도 되므로 `/help /model`은 `/help model`과 같고, 아무 명령도 답하지 않는 이름은 `/help`를 가리키는 모르는 명령으로 알린다. `/keys`는 키 부분만 출력한다. 지금 적용된 키와 동작마다 하는 일을 `ACTIONS`가 선언한 순서로 보여 주고, 키가 없는 동작에는 `(unbound)`를 단다.

## 선택 목록

모델, 추론 단계, 세션, 스킬, 링크와 초안 목록은 같은 선택 창을 씁니다. 창에는 제목, 검색 줄, 선택지별 행과 현재 선택의 위치가 표시됩니다. Enter로 선택하고 Esc로 닫습니다. 방향 키와 페이지 키로 이동하고 Backspace로 검색어를 편집합니다. 창이 열린 동안 입력한 글자는 검색어에 들어갑니다.

거르기는 슬래시 팝업과 같은 부분 수열 맞추기이고, 행의 이름과 두 번째 열, 세션이면 미리보기가 담은 대화 줄까지 본다. 그 줄은 검색 대상이고 미리보기의 머리 줄은 아니다. 머리 줄은 한 디렉터리의 모든 행이 함께 쓰는 디렉터리와 시각을 적기 때문이다. 걸러 낸 행은 점수 순으로 놓이고 점수가 같으면 목록이 준 순서를 지키므로, 거르기가 비어 있으면 목록이 원래 순서대로 보인다. 아무것도 남지 않는 거르기는 `nothing matches that filter`라고 알린다.

선택된 행의 미리보기만큼 패널이 자란다. 가로줄 하나에 행의 글을 최대 여덟 줄 그리고, 패널이 글보다 짧으면 `…`로 자른다. 높이는 지금 선택된 행이 아니라 미리보기가 가장 긴 행을 따른다. 선택을 따라 패널이 커졌다 작아지면 방향 키를 누를 때 목록이 튀기 때문이다. 목록 세 행과 미리보기를 함께 놓을 수 없는 화면은 미리보기를 먼저 버리고 목록을 지킨다.

모델 목록은 지금 쓰는 모델에 `(current)`를 붙이고, 선택된 행은 입력 줄과 같은 표시를 단다(`unicode` 프리셋에서 `❯`). 글자를 입력하면 목록이 걸러지고, `enter`가 행을 고르고 `esc`가 목록을 닫는다. 미리보기는 모델과 프로바이더를 적고 그 행이 지금 쓰는 모델인지 알리며, `enter`가 무엇을 하는지도 알린다. 고르면 전환 요청을 데몬에 보내고, 상태 줄은 데몬이 세션 정체성으로 확인해 준 뒤에야 바뀐다. 거절된 전환은 이전 모델을 그대로 보여 준다.

`/model <name>`은 목록 없이 바로 전환한다.

노력 사다리 목록은 클라이언트가 제공하는 `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`이고, 지금 단계에 `(current)`를 붙이며 행마다 그 단계가 모델에 무엇을 요구하는지 한 줄로 미리 보여 준다. 커서와 미리보기는 그 표시된 행에서 열리므로 `enter`가 지금 단계를 그대로 확인하고 `none`으로 내려가지 않는다. 세션이 단계를 알리지 않거나 사다리에 없는 단계를 알리면 첫 행에서 연다. 행은 클라이언트의 것이므로 목록은 여는 순간 이미 완성되어 있다.

`models.shortlist`에 순환할 모델 ID를 지정합니다. Ctrl+P는 다음 모델로, Ctrl+Alt+P는 이전 모델로 옮깁니다. 목록 끝을 지나면 반대편으로 돌아갑니다. 클라이언트는 순환 전에 데몬의 모델 목록을 확인하고 목록에 없는 ID는 건너뜁니다.

`/switch`와 `/resume`은 같은 저장 세션 목록을 다른 제목으로 연다. 최신 순이고, 행마다 세션 제목(없으면 첫 사용자 줄, 그것도 없으면 아이디)과 마지막으로 바뀐 시각을 담으며, 시각은 행 오른쪽 끝에 맞춰 두어 목록 아래로 읽힌다. 둘 다 들어가지 않는 좁은 화면은 이름을 남긴다. 지금 붙어 있는 세션에는 `(current)`가 붙는다. 미리보기는 디렉터리와 시각으로 시작하고 이어서 최신 메시지 여섯 개를 `you: …`와 `assistant: …` 줄로 보여 준다. 저장된 메시지 가운데 최신 스무 개를 읽고, 주입된 `<system-reminder>` 메시지는 사용자가 쓴 것이 아니므로 뺀다. 데몬이 다시 읽어 주지 못하는 세션은 제목을, 제목이 없으면 아이디를 이름표로 두고 머리 줄만 있는 미리보기를 쓴다.

행을 고르거나 `/switch <id>`, `/resume <id>`를 입력하면 곧바로 붙고, 데몬은 여섯 글자 이상의 유일한 접두사도 받는다. 붙으면 이전 세션의 화면을 지우고 저장된 대화를 사용자 메시지와 어시스턴트 메시지로 다시 그리며, `started a new session <id>` 또는 `resumed <id>`를 남기고, 새 세션의 정체성에서 모델, 프로바이더, 노력 단계, 제목을 받는다. 그래서 상태 줄은 계속 `provider/model`을 보여 준다. `/new`는 이 디렉터리의 세션을 요청해 같은 방식으로 옮겨 가고, 떠나온 세션은 저장된 채로 남는다. 클라이언트는 떠나온 모든 세션의 이벤트를 버리므로 두 대화의 행이 서로에게 닿지 않는다. 세션 변경은 턴이 돌거나 모델이나 노력 단계 변경이 아직 적용 중이면 기다리고, 메시지 없이 떠난 새 세션은 데몬이 보관하지 않으므로 다시 붙을 수 없다.

`/skills`는 하네스가 이 세션에 보고한 스킬을 나열한다. 이름, 두 번째 열의 하네스 설명, 그리고 스킬을 읽은 파일과 쓸 수 있는 도구를 적고 `enter`가 초안에 그 호출을 넣는다는 줄로 끝나는 미리보기다. 행을 고르면 `/skill:<name>`과 뒤따르는 공백 하나를 보내지 않고 편집기에 쓰므로, 그 뒤의 요청은 사용자가 적는다.

`/links`는 최근 어시스턴트 답변 8개에서 HTTP와 HTTPS 링크를 최신순으로 표시합니다. 행에서 Enter를 누르면 표시된 주소를 시스템 브라우저에서 엽니다. Esc를 누르면 목록이 닫힙니다. 잘못된 주소, 로컬 파일과 자격 증명이 포함된 링크는 목록에서 빠집니다.

패널을 그리기에 화면이 너무 작으면 선택 목록과 설정 화면이 패널 대신 한 줄을 그린다. `list hidden: window too small, esc closes`이거나 `settings hidden: window too small, esc closes`이다. 그때도 오버레이는 모든 키를 가져가므로 `esc`로 닫는다.

## 상태 줄

화면 맨 아래 줄은 이름 붙은 세그먼트로 조립한다. 데이터가 없는 세그먼트는 아무것도 그리지 않고, 모르는 이름은 경고를 남기고 건너뛰므로 나머지 줄은 그대로 그려진다.

| 세그먼트 | 보여 주는 것 |
| --- | --- |
| `status` | 턴이 하는 일: 클라이언트가 직접 쓰는 `idle`, `running`, `requires_action`, `disconnected`, 또는 데몬이 보고한 세션 상태 |
| `model` | `provider/model`에 추론 노력 단계를 이어 붙인 것, 또는 데몬이 보고한 둘 중 있는 쪽 |
| `session` | 세션 아이디를 줄인 것 |
| `path` | 작업 디렉터리. 홈 디렉터리는 `~`로 줄이고, 긴 경로는 세그먼트 경계에서 자른다 |
| `tokens` | 마지막 요청의 입력·출력 토큰. `↑in ↓out` |
| `context_pct` | `statusline.context_window`에서 쓴 비율. 설정이 `0`이면 숨긴다 |
| `time` | 현지 시각 `HH:MM` |
| `pending` | 대기 중인 승인이나 질문 |

`status`는 그 말이 모두 클라이언트의 것이 아닌 유일한 세그먼트다. 클라이언트는 `idle`, `running`, 프롬프트를 기다리는 동안의 `requires_action`, 연결이 끊겼을 때의 `disconnected`를 직접 쓰고, 데몬의 `generating`은 `running`으로, 멈춘 턴을 데몬이 다시 말한 `cancelled`는 `idle`로 그리며, 그 밖의 비어 있지 않은 세션 상태는 데몬이 보낸 그대로 보여 준다. 그래서 이 문서가 나열하지 않은 말도 그 자리에 나올 수 있다. 세션에 막 붙었을 때의 `attached`가 그런 예다.

`statusline.preset`이 배치를 고른다.

| 프리셋 | 왼쪽 | 오른쪽 |
| --- | --- | --- |
| `default` | `status`, `model`, `path` | `tokens`, `context_pct`, `time` |
| `minimal` | `model` | `status` |
| `custom` | `statusline.left`가 이름한 것 | `statusline.right`가 이름한 것 |

`model` 세그먼트는 데몬이 그 모델의 값으로 보고한 추론 노력 단계를 프리셋의 구분자로 이어 붙인다. 구분자는 프리셋이 따로 그리지 않으면 `·`이고, 예를 들어 `provider/model · high`다. 노력 단계가 없거나 비어 있으면 아무것도 붙이지 않고, 모델 이름 없이 노력 단계만 있으면 그리지 않는다. 클라이언트는 첫 키 입력 전에 하네스에 이 세션이 무엇으로 도는지 묻기 때문에 첫 화면이 이미 모델과 노력 단계를 적는다. 데몬이 보고를 거절하면 둘 다 모르는 채로 남고 `could not read the runtime info: <error>` 경고 한 줄이 붙으며, 세션에 붙거나 새 세션을 시작한 뒤 오는 정체성 이벤트가 같은 두 값을 채운다. 줄이 터미널에 들어가지 않으면 중요도가 낮은 세그먼트부터 버린다. 우선순위는 `time`(가장 먼저 버림), `session`, `tokens`, `context_pct`, `path`, `pending`, `status`, `model`(가장 나중에 버림) 순이다. 마지막으로 남은 세그먼트는 화면보다 넓어도 남긴다. 잘린 모델 이름이 빈 줄보다 쓸모 있기 때문이고, 그 자리에서 가장 먼저 포기하는 것이 노력 단계라서 잘리는 자리는 뒤에 아무것도 없는 구분자 다음이 아니라 모델 이름 안이다.

## 명령

`/`로 시작하는 줄은 내장 명령, `skill:` 주소, 명령 파일, 하네스 명령, 스킬의 맨이름 순으로 찾는다. 내장 명령은 그 이름을 온전히 가지므로 같은 이름의 명령 파일은 내장이 이긴다고 표시되고 실행되지 않는다. 모르는 이름은 `/help`를 가리키는 오류가 되고, `//`로 시작하는 줄은 슬래시 하나를 뺀 그대로의 메시지로 보낸다.

| 명령 | 하는 일 |
| --- | --- |
| `/clear` | 트랜스크립트 창을 지운다 |
| `/effort [level]` | 추론 노력 단계를 정하거나, 사다리에서 고른다 |
| `/exit` | `/quit`과 같이 나간다 |
| `/help [command]` | 명령과 각 명령의 출처, 지금 적용된 키를 나열하거나, 명령 하나를 설명한다 |
| `/keys` | 지금 적용된 키와 동작마다 하는 일을 나열한다 |
| `/links` | 최근 어시스턴트 답변의 링크를 나열하고 선택한 주소를 연다 |
| `/model [name]` | 목록에서 모델을 고르거나, 이름을 준 모델로 전환한다 |
| `/new` | 이 디렉터리에서 새 세션을 시작한다 |
| `/quit` | 나간다 |
| `/resume [id]` | 저장된 세션을 다시 그리거나, 목록에서 고른다 |
| `/settings` | 설정 화면을 연다 |
| `/skills` | 하네스가 보고한 스킬을 나열하고 그 가운데 하나를 초안에 넣는다 |
| `/switch [id]` | 다른 저장 세션으로 옮기거나, 목록에서 고른다 |

이 표에는 클라이언트 명령(`crates/tui/src/commands/mod.rs`의 `Local`)을 이름순으로 적었습니다.

하네스 명령은 붙어 있는 런타임에서 돌고 모델의 프롬프트로는 가지 않는다. `/help`는 명령마다 행 하나를 그리고 설명을 한 열에 맞춘다. 내장 명령이 먼저, 그다음 하네스 이름이 이름 순으로, 그다음 명령 파일, 그다음 하네스가 보고한 스킬, 마지막으로 키가 온다. 트랜스크립트는 이 목록 전체를 공지 하나로 그리므로 첫 행에 공지의 글머리표가 붙고 그 뒤의 모든 행에 두 칸이 더해진다. 아래 예시는 그 여백을 뺀 목록이다.

```text
built-in commands:
  /clear               clear the transcript
  /effort              set the reasoning effort, or pick one from the ladder
  /exit                leave, the same as /quit
  /help                list the commands and the keys in force
  /keys                list the keys in force and what each does
  /links               list the http(s) links in recent answers and open one
  /model               pick a model, or switch with /model <name>
  /new                 start a new session in this directory
  /quit                leave
  /resume              replay a stored session, or pick one from the list
  /settings            open the settings screen
  /skills              list the skills the harness reports, and put one in the draft
  /switch              move to another stored session, or pick one from the list
harness commands:
  /agents              list the agent models, and switch one for this session or every session
```

어떤 하네스 이름이 몇 개 나오는지는 소켓 반대편에 붙은 빌드가 답하는 몫이다. 이 목록은 이 문서가 아니라 그 데몬에서 온다.

명령 파일은 인자 힌트와 설명과 함께 `/help`에 나온다. 명령 파일이 하나도 없으면 `/help`가 어디에 두는지 알려 준다.

`/switch`는 다른 저장 세션으로 옮기고, 모델 선택은 `/model`의 몫이다. 이름을 주거나 `alt+p`가 여는 목록을 쓴다. omp의 `/switch`는 대신 모델을 바꾸지만 여기서는 둘이 다른 명령이고, `/switch`는 떠나온 세션의 모델을 건드리지 않는다.

`/skills`는 하네스가 이 세션에 보고한 스킬을 나열한다. 목록에 있는 이름은 `/skill:<name>`으로 답하고, 내장 명령이나 하네스 명령, 명령 파일이 그 이름을 이미 차지하지 않았으면 맨이름으로도 답한다. 줄은 보내기 전에 펼쳐진다. 이름 뒤에 아무것도 없으면 `Read skill://<name> and follow its instructions.`이고, 뒤에 말이 붙으면 `Read skill://<name> and follow its instructions for this request: <text>`이다. 하네스 API에는 스킬을 활성화하는 호출이 없으므로 고른 스킬은 그 읽기 요청으로 보내고, 세션이 그 주소를 읽을 수 있는 만큼 동작한다. omp는 스킬 글을 스스로 읽어 보내지만 이 클라이언트는 읽어 달라고 요청한다.

`/effort`는 사다리에서 단계 하나를 받는다. `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`이고 대소문자를 가리지 않으며, 그 밖의 이름은 요청이 클라이언트를 떠나기 전에 거절하고 경고에 사다리를 적는다. 단계 없이 부르면 사다리 목록을 열고, `shift+tab`은 지금 단계에서 같은 사다리를 걸어 마지막 단계를 지나면 처음으로 돌아온다. 사다리는 프로바이더의 것이 아니라 클라이언트의 목록이므로 어느 단계가 있는지는 프로바이더가 정한다. 없는 단계는 오류로 돌아오고 상태 줄은 그 전 단계를 그대로 둔다.

`/keys`는 `/help`의 키 부분만 출력하고, 화면보다 긴 목록은 다음 전송이나 `ctrl+end`까지 끝이 아니라 첫 행부터 그린다.

`/context`만은 클라이언트가 글자로 찍지 않고 측정된 패널로 직접 그리는 하네스 명령이다. 데몬은 다음 요청이 싣는 재료와 부분별 추정치를 함께 답하고, 클라이언트는 숫자만 남기고 본문은 버린다. 첫 줄은 `context · ~8.7k of 200k tokens (4%)`이고, 그 아래로 요청이 싣는 부분마다 한 줄씩 `system prompt`, 요청이 보내는 도구 수와 그중 지연된 수를 붙인 `tools`, 담긴 메시지 수를 붙인 `messages`, 그리고 `free`가 놓인다. 각 줄에는 창 전체를 기준으로 한 막대가 붙으므로, 늘어난 부분이 곧 늘어난 막대다. 비용이 있는 부분은 항상 한 칸 이상을 차지하고, 추정치가 창의 80%에 이르면 경고 색으로 `near the limit`이 붙는다. 숫자는 프로바이더가 보고한 사용량이 아니라 데몬이 프롬프트, 도구 목록, 보이는 대화로 계산한 추정치다. 빌드가 창 크기를 모르면 퍼센트와 `free` 줄을 빼고, 막대를 그릴 폭이 없는 창에서는 줄만 남기고 막대를 뺀다. 내역을 모르는 옛 데몬이면 그 명령이 보낸 메시지를 그대로 보여 준다.

나머지 하네스 명령은 데몬이 쓴 메시지를 그대로 찍는다. 다만 메시지가 자기 페이로드를 JSON으로 직렬화한 명령은 예외이며 `/auth`와 `/swarm`이 대표적이다. 그런 답은 옆에 실린 `data`로 라벨 블록을 그린다. 명령 제목을 강조 색으로 쓰고, 중첩 단계마다 `라벨  값` 행을 같은 열에 맞추며, 목록은 `key · 개수` 제목 아래 요소마다 이름을 붙인 한 줄로 놓는다. 켜고 끄는 값은 `yes`/`no`, 없는 값은 `—`, 설명문은 맨 끝에 둔다. `api_key`, `*_token`, `*_secret`, `password`처럼 비밀을 담는 키의 문자열은 `— hidden`으로 가리고, `api_key_env` 같은 변수 이름은 비밀이 아니므로 그대로 보여 준다. 긴 값은 제 값 열 아래로 접힌다. `/skills`, `/plan`, `/remote pair`처럼 산문으로 답하는 명령은 쓴 문장을 그대로 유지하며, 페이로드를 JSON으로 그리는 일은 없다.

## 설정 화면

`/settings`는 설정 레지스트리에서 생성된다. 키마다 행 하나를 Appearance, Status line, Editor, Transcript 탭으로 묶고, 레지스트리가 선언한 이름표와 설명을 쓴다. 행마다 값이 온 계층도 함께 보여 준다.

`/`를 누르면 설정 이름, 키 또는 설명으로 모든 탭을 검색합니다. 결과 행에는 각 항목이 속한 탭도 표시됩니다. Enter를 누르면 검색 결과를 유지한 채 목록으로 돌아갑니다. 검색하거나 결과 사이를 이동해도 설정값은 그대로입니다.

| 키 | 하는 일 |
| --- | --- |
| `/` | 모든 탭의 설정을 검색하거나 현재 검색어를 편집한다 |
| `up`, `down` | 행 사이를 옮긴다 |
| `left`, `tab` | 이전 탭으로 옮긴다 |
| `right`, `shift+tab` | 다음 탭으로 옮긴다 |
| `enter` | 그 행의 편집기나 고르기 목록을 열거나 확정한다 |
| `esc` | 편집기나 선택 목록을 닫고, 검색을 해제한 다음 화면을 닫는다 |

키의 형식이 거절하는 값은 인라인 오류로 보이고 아무것도 쓰지 않는다. 저장은 전역 `tui.toml`로만 가고, 프로젝트 계층과 `--config` 계층은 다시 쓰지 않는다.

파일은 제자리에서 파싱하고 고치므로, 이미 파일에 있는 주석과 키 순서와 배치가 저장 뒤에도 남고, 클라이언트가 시작한 뒤에 손으로 고친 키는 그 값을 지킨다. 파싱할 수 없는 파일은 `cannot parse <path>: ...; refusing to overwrite it`으로 거절한다. 덮어쓰면 사용자의 작업을 잃기 때문이다. 저장이 끝나면 어느 경로에 썼는지 트랜스크립트에 확인으로 남고, 파일보다 우선하는 환경 변수는 그 뒤에도 이긴 계층으로 보인다.

## 클라이언트 설치

릴리스는 클라이언트를 에이전트 옆의 별도 압축 파일로 배포한다. 이름은 `horon-tui-<platform suffix>.tar.gz`이고, 접미사는 에이전트 자산과 같다(`horon-tui-linux-x86_64.tar.gz`, `horon-tui-macos-aarch64.tar.gz`, `horon-tui-windows-x86_64.tar.gz` 등). 설치에서 달라지는 것은 없다.

`scripts/install/install.sh`와 `scripts/install/install.ps1`은 이 압축 파일을 에이전트 자산 옆으로 받아 `SHA256SUMS`로 검사한다. `horon install-release`는 이를 `builds/versions/<version>/`의 `horon-agent` 옆에 넣으므로, 버전 디렉터리에 두 바이너리가 함께 있고 활성화가 둘을 함께 바꾼다.

압축 파일은 모든 단계에서 선택 사항이고, 검증할 수 없는 사본이 에이전트를 막는 일은 없다.

- 플랫폼용 압축 파일을 배포하지 않는 릴리스는 그 사실을 한 줄로 알리고 `horon-agent`만 설치한다.
- `SHA256SUMS` 항목이 없거나 다이제스트가 맞지 않으면 한 줄을 출력하고 에이전트 바이너리만 설치한다.
- 소스 빌드(`--source-binary`)와 FreeBSD는 배포된 클라이언트를 넣지 않는다. FreeBSD는 `horon-agent`만 배포한다.
- 이미 `horon-agent`가 들어 있는 버전 디렉터리는 그 파일이 없을 때만 클라이언트를 더한다. 그 밖에는 버전이 불변이다.

`scripts/install/uninstall.sh`와 `scripts/install/uninstall.ps1`은 설치 디렉터리의 `horon-tui` 런처를 다른 대상과 함께 나열하고 함께 지운다. 예전 설치가 남긴 것도 지운다.

## 알려진 한계

- FreeBSD는 `horon-agent`만 배포하므로 클라이언트를 설치하지 않고, 인자 없는 `horon`은 형제 파일이 없다고 알린다.
- Linux와 macOS에서 핸드오프는 프로세스 하나가 다른 하나를 대체하는 방식이므로, 클라이언트가 끝나면 터미널 명령도 함께 끝나고 종료 코드는 클라이언트의 것이다. Windows에서 런처는 클라이언트를 띄우고 곧바로 코드 0으로 끝나므로, 그 코드는 클라이언트에 대해 아무것도 말하지 않는다.
- `SIGTERM`, `SIGHUP`, `SIGQUIT`은 `/quit`과 같은 경로로 터미널을 되돌리고(마우스 캡처와 bracketed paste 끄기, 셸 제목 복구) 다시 그 신호를 스스로에게 보내므로, 감싼 스크립트는 여전히 클라이언트가 신호로 죽었다는 것을 본다(`SIGTERM`이면 143). `SIGKILL`은 잡을 수 없으므로 그렇게 죽은 클라이언트는 두 모드를 켠 채로 남긴다. Windows는 콘솔이 프로세스와 함께 정리되므로 핸들러를 설치하지 않는다.
- 디스크에서 고친 테마 JSON 파일은 테마 로더가 1초 확인에서 다시 읽지만, 그것만으로 화면을 다시 그리지는 않는다. 노는 클라이언트는 다음 키, 이벤트, 설정 재적용이 있을 때까지 지금 그림을 유지한다.
- 표와 링크는 모델이 적은 원문으로 보이고, 한 칸이나 세 칸 들여쓴 목록은 단계 하나가 두 칸이므로 온전한 단계 수로 내림된다.
- 프롬프트가 열려 있는 동안 키보드는 프롬프트의 것이다. 슬래시 명령을 입력할 수 없고, 프롬프트 키인 글자는 프롬프트에 답한다(`a`는 `/clear`의 시작이 아니라 "allow always"다).
- `\` 하나로 끝나는 초안은 적은 그대로 보내지 않는다. 그 백슬래시는 줄을 잇고, `\\`는 백슬래시 두 개로 보낸다.
- 노력 사다리는 클라이언트의 것이므로, 어떤 단계가 없는 프로바이더는 그 단계를 거절하고 상태 줄은 그 전 단계를 그대로 둔다.
- 노력 단계는 바뀔 때마다 서버에 저장되고, 턴이 도는 동안 바꾼 값은 그 턴이 끝날 때까지 미뤄지므로 턴 중에 고른 단계는 그때까지 효력을 내지 않는다.
- 클라이언트는 연결할 때마다, 세션에 붙을 때마다, 새 세션을 시작할 때마다 하네스에 그 세션의 스킬 목록을 묻고, 데몬은 그 답마다 전역 스킬 디렉터리를 다시 읽는다.
- 데몬이 스스로 시작한 턴은 이 클라이언트에 시작 이벤트를 보내지 않으므로 `esc` 전달 표시가 움직이지 않는다. `esc`로 보낸 메시지는 끝난 턴으로 보낸 것으로 그려진 채 남는다.
- `--session <id>`로 시작하면 저장된 대화를 그리지 않고 붙기만 한다. `/resume <id>`는 그 대화를 다시 그린다.
- 팝업이 닫혀 있으면 탭은 내장 명령, 하네스 명령, 명령 파일의 이름만 완성한다. 스킬 이름은 팝업에서 채우거나 `/skills`에서 고른다.
- 확장되는 것은 남아 있는 도구 호출 가운데 가장 최근 것 하나뿐이다. 확장은 보기를 대화 끝으로 옮기고, 64 KiB보다 긴 사본은 `… output truncated`로 자르며, `ctrl+o expands` 이름표는 표시와 함께 한 행에 들어가지 않을 때 뺀다. 세 자리 줄 수에서는 29칸 아래가 그런 경우다.
- 첫 답이 오기 전에 두 번째 `/new`를 입력하면 그 세션은 재개로 보고된다. 클라이언트가 시작 중인 세션을 표시 하나로 들고 있기 때문이다.
- 세션 목록은 보여 주는 세션마다 데몬에 한두 번 물으므로, 세션이 많은 디렉터리에서는 세션을 읽어 오는 동안 목록과 그 뒤의 이벤트가 늦어진다.
- 세션 미리보기는 저장된 메시지 가운데 최신 스무 개를 읽고, 주입된 `<system-reminder>` 메시지는 빼며, 데몬이 다시 읽어 주지 못하는 세션은 머리 줄만 보여 준다.
- 메시지 없이 떠난 새 세션은 데몬이 보관하지 않으므로 다시 붙을 수 없다.
- 스킬은 `skill://<name>`을 읽어 달라는 요청으로 보내므로 세션이 그 주소를 읽을 수 있을 때만 동작한다.
- `esc`는 화면에 제 힌트를 두지 않는다. 그 키와 하는 일은 `/keys`에 적혀 있다.
- `editor.submit_on_enter`는 전송 키 처리가, `transcript.show_reasoning`은 트랜스크립트가 읽는다. 둘 다 바꾼 뒤 다음 키 입력과 다음 추론 조각부터 적용된다. `--hide-thinking`이나 `ctrl+t`로 만든 세션 선택은 그 설정 값 자체가 바뀔 때까지 설정보다 우선하므로, `tui.toml`의 다른 키를 고쳐도 설정이 세션 선택을 되돌리지 않는다. 나머지 트랜스크립트 설정과 상태 줄은 파일이 다시 적용되는 즉시, 곧 화면을 다시 그리면서 효력을 낸다.
