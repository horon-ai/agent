# Documentation site (agent.horon.ai)

The [Mintlify](https://mintlify.com) project in this folder is published at
`https://agent.horon.ai`. `docs.json` holds the theme, the navigation and the
site settings, each `*.mdx` file is one page, `logo/` and `favicon.svg` are the
brand assets, and `index.mdx` is the home page. The package is managed with bun;
the Mintlify CLI (`mint`) is a dev dependency, so no global install is needed.

## Work on the site

```bash
bun install --frozen-lockfile
bun run dev           # mint dev: preview at http://localhost:3000
bun run check         # mint validate (strict build) and mint broken-links
```

`mint dev` copies static assets (logos, favicon) at start-up, so restart it after
changing one. A page that is not listed in `docs.json` `navigation` is hidden from
the sidebar but still reachable by URL; add the page path (no leading slash, no
extension) to a `pages` array when you add a file. When a page moves, add a
`redirects` entry in `docs.json` and run `bunx mint broken-links --check-redirects`.

`bun run check` also runs in CI (`Documentation Site` job). It does not deploy.

## How it is published

Mintlify builds and deploys from the GitHub repository, not from CI. Push to the
deployment branch and the site rebuilds in a few minutes; the Publishes page
(<https://app.mintlify.com/publishes>) shows the build status.

One-time setup in the Mintlify dashboard:

1. Install the Mintlify GitHub App on `horon-ai/agent` (Git Settings, choose
   **Only select repositories**). It needs an organization owner or a repository
   admin.
2. In Git Settings, turn on **docs.json is in a subdirectory** and enter
   `/packages/docs-site` (no trailing slash).
3. Set the deployment branch to `dev`. `main` is the release branch and takes
   changes only through a release merge.

## Custom domain

Add `agent.horon.ai` to the Mintlify project, from the dashboard (Custom domain
setup) or from a terminal after `bunx mint login`:

```bash
bunx mint add-domain agent.horon.ai
```

The command prints the DNS records. Add them at the DNS provider of `horon.ai`:

| Type | Name | Content |
| --- | --- | --- |
| `TXT` | `_acme-challenge.agent` | value printed by Mintlify |
| `TXT` | `_cf-custom-hostname.agent` | value printed by Mintlify |
| `CNAME` | `agent` | `cname.mintlify.builders` |

Add the two `TXT` records first. Change the `CNAME` only after both show as
verified in the dashboard, or HTTPS breaks until the certificate is issued. If the
zone is on Cloudflare:

- A proxied (orange cloud) record cannot verify before the `CNAME` points to
  Mintlify. Set the `CNAME` to **DNS only** (gray cloud) for a switch with no
  downtime.
- Set SSL/TLS to **Full (strict)** and turn **Always Use HTTPS** off, because the
  HTTPS redirect blocks the Let's Encrypt validation.
- A CAA record, when the zone has one, must allow `0 issue "letsencrypt.org"`.

Until the switch, `agent` is a `CNAME` to `horon-agent-docs.pages.dev` (the
retired Cloudflare Pages project). Replacing it is the moment the Astro site
stops serving, so do it after the Mintlify build is live at its
`<subdomain>.mintlify.site` address. `docs.json` already sets
`seo.metatags.canonical` to `https://agent.horon.ai`.

## Verify a deployment

```bash
dig +short CNAME agent.horon.ai                     # cname.mintlify.builders
curl -sS -o /dev/null -w '%{http_code}\n' https://agent.horon.ai/
curl -sS -o /dev/null -w '%{http_code}\n' https://agent.horon.ai/getting-started
curl -sS https://agent.horon.ai/llms.txt | head -5  # generated by Mintlify
curl -sS -o /dev/null -w '%{http_code}\n' https://agent.horon.ai/no-such-page   # 404
```

`sitemap.xml`, `robots.txt`, `llms.txt`, `llms-full.txt` and the search MCP server
(`/mcp`) are generated by Mintlify, so none of them lives in this folder.
