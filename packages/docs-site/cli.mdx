Bare `horon` checks terminal handoff conditions first (`stdin` and `stdout`
are terminals, `HORON_NO_TUI` is unset, `horon-tui` sits beside the binary);
only when all hold does it start the server if needed and replace itself with
`horon-tui`. A pipe, `HORON_NO_TUI=1`, or a missing sibling starts no daemon,
prints the condition and its remedy (or the install hint only when the sibling
is missing), then exits `1`. Running `horon-tui` directly exits `1` on a pipe
without entering the alternate screen and renders `"terminal too small"` below
`20x6`.

## Core commands

| Command | What it does |
| --- | --- |
| `horon run "<message>"` | Send one message, run tools until the turn ends, exit. Exits `1` on guardrail stops (e.g. `content_filter`), `length`, or empty turns; `auto_poke` defaults to `6` follow-up turns (`HORON_AGENT_RUN_AUTO_POKE=0` disables, stops early on unchanged todos). `--max-cost <USD>` rejects unpriced remote routes upfront (`1`) while explicitly local unpriced endpoints warn on stderr. `--json` prints a machine-readable result, `--ndjson` streams events. |
| `horon repl` | One line at a time in the terminal, without the full-screen client. |
| `horon serve` | Background agent daemon on a Unix socket (or named pipe on Windows; `HORON_AGENT_SOCKET`). |
| `horon api-bridge` | Harness API for SDK clients on a Unix socket or Windows named pipe (`HORON_AGENT_API_SOCKET`), with optional bearer-authenticated `--api-bind <IP:PORT>` TCP listener (`alias: api`). |
| `horon acp` | ACP v1/v2 adapter on stdio for editors. |
| `horon rpc` | stdio JSONL RPC adapter for a host program that owns the process: one JSON command per line in, one frame per line out. `--mode rpc` selects the same adapter. |
| `horon server start\|reload\|stop\|promote` | Manage the daemon. Prefer `reload` after an upgrade: it hands live sessions to a freshly exec'd server instead of dropping them. `stop` requires `--force`. |

`api-bridge` listens as `horon-agent-api.sock` in the runtime directory, which is
`HORON_AGENT_RUNTIME_DIR` when set, else `XDG_RUNTIME_DIR`, else the platform's
per-user runtime directory (on macOS, `$TMPDIR`), or a derived named pipe on
Windows; `--api-socket <path>` moves it, `--api-bind <IP:PORT>` adds an
authenticated TCP listener (`--api-insecure-behind-proxy` for non-loopback behind
TLS), and `--stdio` (Unix only) serves one connection on stdin/stdout for SSH
clients. The global `--socket` selects the *internal daemon* socket, which is a
different socket.

## Providers and models

| Command | What it does |
| --- | --- |
| `horon provider list` | Provider ids you can pass to `-p/--provider`. |
| `horon provider status [--json]` | Local credential source and status per configured profile without calling providers. |
| `horon provider current [--json]` | The currently requested and resolved provider selection. `--json` reports `"ready"`. |
| `horon provider failover [--json]` | Read-only preview of retry and failover order produced by configuration. |
| `horon provider diagnose [--check] [--json]` | Check configured profiles (`--check` queries model lists for supported wires). |
| `horon provider add <name> --type <type> --base-url <url> --model <id>` | Add a profile. `--type` takes `openai-compatible` (default), `openai-responses`, `anthropic-compatible`, or `gemini-compatible`, and without `--auth` the command writes no `auth` line so the type default applies. `--api-key-stdin` keeps the key out of shell history, `--auth none` suits a local endpoint, and `--set-default` also writes `[provider] default_provider`. |
| `horon model list [--refresh] [--profile <name>]` | Model names you can pass to `-m/--model`. |

## Sessions

`horon session` (alias `horon sessions`) works on the event store:
`inspect`, `doctor`, `migrate`, `export`, `import`, `export-legacy`,
`recover-to`, `rename`, `archive`, `restore`, `delete`.

`horon session inspect <session> [--json]` is read-only: it reports the store
layout, the heads, the archive state and any damage.

`horon export <session> [--json] [--out FILE]` prints a Markdown transcript (or
wraps it as `{"session_id": ..., "markdown": ...}`).
Secrets are redacted and tool results over 4 KiB are truncated; the output matches
the `export_session_markdown` harness API reply.
`horon export <session> --html [--json] [--out FILE]` writes the same redacted projection
as a standalone offline HTML report instead: every transcript character is
escaped, the stylesheet is inline, and a Content-Security-Policy forbids any
network load, so the saved file opens without a connection. Unlike the Markdown
form, an `--out` path that already exists is refused. Passing `--json --out FILE`
writes the JSON payload (`{"session_id": ..., "markdown"|"html": ...}`) to `FILE`
and prints a JSON summary (`session_id`, `out`, `format`, `bytes`) to stdout.
`horon session export <session>
--output <dir>` is a different command: it writes the original events and blobs
as a bundle into a directory that must not exist yet, and `horon session import`
reads that bundle back.

`horon session archive` and `horon session restore` only record a state change.
`horon session delete <session> --yes` is the one destructive command: the
transcript, todos, the goal attachment, artifacts and the runtime journal all go,
and a session a running daemon has open is refused.

## Unattended runs

| Command | What it does |
| --- | --- |
| `horon runtime-state show --session <id>` | List the live inputs of a session and which ones are undetermined; exits `1` when `<id>` has no stored session or runtime journal. |
| `horon runtime-state resolve-input --session <id> --input <id> --action retry\|cancel` | Settle an input whose outcome is unknown. |
| `horon approvals resolve --request-id <id> --tool-call-id <id> --verdict retry\|skip` | Record a human verdict for a run that stopped waiting on a person. |

| `horon stream-rules [TEXT]` | Validate stream rules and optionally preview a sample. |

| `horon permissions` | Review and answer pending ambient permission requests. |

| `horon debug <command> [arg]` | Talk to a running daemon over the debug socket. |

## Editors (ACP)

Register `horon` (or `horon-agent`) with the argument `acp` as an external agent.
In Zed (`settings.json`):

```json
{
  "agent_servers": {
    "horon agent": {
      "type": "custom",
      "command": "/absolute/path/to/horon",
      "args": ["acp"]
    }
  }
}
```

JetBrains, Neovim and VS Code ACP plugins take the same two values. The `initialize`
response advertises `authMethods` with one method, `horon-agent-credentials`,
which checks whether the credentials of a `[providers.<name>]` profile can be used
to call models. Register a profile with `horon provider add`; this build has no
login command for the editor to run in a terminal.
