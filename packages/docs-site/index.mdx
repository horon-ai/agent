title: "horon agent"
description: "Run horon from the terminal, an SDK or an editor. Both headless and TUI mode use the same agent engine and session history."
---

Use `horon` to open the interactive terminal client or `horon run` to send one
prompt from a script. Both modes use the same engine, tools and saved sessions.
The agent connects to the model endpoint you set in your provider profile.

Use the shell installer on macOS, Linux or FreeBSD. FreeBSD ships the agent
binary only. For Windows, use the [PowerShell installer](/install).

```sh
curl -fsSL https://raw.githubusercontent.com/horon-ai/agent/main/scripts/install/install.sh | bash
```

Once you have [configured a provider](/getting-started#first-turn), check the
active profile and run a turn:

```sh
horon provider current --json
horon run "summarize this repo"
```

## At a glance

<CardGroup cols={3}>
  <Card title="Two binaries">
    `horon-agent` runs the agent: `serve`, `run`, `repl`, `api-bridge`, `acp`, `rpc`.
    The terminal client `horon-tui` is separate and built on the SDK.
  </Card>
  <Card title="Append-only sessions">
    History is an event log with content-addressed blobs. Archive, compaction and
    rewind append records and never delete an original.
  </Card>
  <Card title="ACP v1 and v2">
    Editors negotiate either version; `initialize` answers with the highest both
    sides support.
