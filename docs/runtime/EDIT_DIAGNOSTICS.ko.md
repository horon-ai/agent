# 편집 후 언어 서버 진단

언어: [English](EDIT_DIAGNOSTICS.md) | **한국어**

상태는 #558 설계 제안이다. 직접 호출하는 LSP 도구는 진단과 이름 바꾸기, 코드 작업을 제공한다. 이 설계는 Horon이 편집 결과를 기록한 뒤 읽기 전용 보고를 선택해서 받는 방법을 추가한다. [도구 참조](TOOLS.ko.md)

## 설계 결정

| 선택지 | 결과 |
| --- | --- |
| 편집마다 포매터 실행 | 새 쓰기가 생기고 프로젝트 명령이 실행될 수 있다. |
| 기존 LSP 등록부에서 진단 조회 | 신뢰하는 서버 선택을 재사용하고 제한된 보고를 돌려준다. 이 방식을 선택한다. |
| 수동 진단만 사용 | 제어권을 유지하지만 턴이 긴 워커에서는 편집 직후 결과를 놓칠 수 있다. |

## 예약과 신뢰 경계

워크스페이스나 세션별로 기본값이 꺼진 설정을 켠다. 프로세스 단위 비활성화가 우선하며 워커에도 전달된다. 워커는 자기 진단을 끌 수 있다. 직접 호출하는 LSP 도구와 같은 워크스페이스 신뢰와 서버 권한을 요구한다. 이미 실행 중인 서버만 사용하므로 이 경로에서 언어 서버나 포매터를 시작하지 않는다. 서버가 없으면 `unavailable`을 보고하고 편집은 성공으로 유지한다.

편집 경로에서 성공적으로 기록한 변경 파일을 읽는다. 실패했거나 되돌렸거나 내용이 그대로인 편집과 임의 셸 쓰기는 제외한다. 워크스페이스 안의 경로를 확인한다. 워커 간에 작업 공간, 경로와 기록한 콘텐츠 버전으로 중복을 제거한다. 같은 경로에 새 버전이 대기하면 최신으로 합치고 이전 버전의 응답은 버린다. 등록부의 문서 동기화를 쓰고 버전이 일치하거나 요청과 연결된 새 응답만 받는다. 그 외에는 `stale`로 보고한다. 한 묶음에 변경 파일 8개, 파일당 진단 20개, 서버당 진행 중 요청 하나, 묶음당 500 ms로 제한한다. 시간 초과나 취소 때는 요청 자리를 반환하고 일부를 검사하지 못했음을 알린다. 진단 문구가 추가 편집이나 도구 실행을 일으키지 않는다.

## 구현 경계

1. `crates/base/src/config.rs`에 선택 실행 설정과 워커에 적용되는 비활성화 규칙을 정의한다. 모의 워커 설정으로 우선순위를 검사한다.
2. `crates/app-core/src/tool/`에서 편집 후 기록된 변경을 수집한다. `crates/app-core/src/tool/lsp.rs`는 등록부로 버전이 맞는 진단을 조회하고 제한된 요약을 만든다. 수동 포매팅과 코드 작업은 별도 동의를 받는다.
3. GitHub Actions에서 모의 서버와 격리한 워크스페이스를 사용한다. TUI 의존성 없이 기존 편집 결과에서 진단을 돌려준다.

## 검증

`cargo test --locked -p horon-agent-app-core --lib`를 실행한다. 기능을 켜고 `example.rs`에 같은 새 내용을 두 번 쓰며 `other.rs`는 건드리지 않는다. `example.rs` 보고는 하나가 나오고 `other.rs` 요청은 없어야 한다. 모의 서버가 상한 이후에 답하면 편집은 유지하고 시간 초과를 알린다. 프로세스 비활성화, 서버 없음, 편집 실패 또는 신뢰하지 않는 작업 공간에서는 요청과 추가 쓰기가 없어야 한다. 이전 응답은 새 보고를 덮어쓰지 못해야 한다.
